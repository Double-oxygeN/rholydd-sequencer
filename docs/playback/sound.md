# 音（経路・音色・ミキサー・FX）

音の経路、パートごとの音源と音色、ミキサーとソロ、ダッキング、ダイナミクスとクリップの検出、FX のオートメーション、スペクトラムアナライザーの取り出しをまとめます。

関係するコード: `src/engine/audio.ts`、`src/engine/oscillator-release.ts`、`src/engine/source-disposal.ts`、`src/engine/strips.ts`、`src/engine/voices.ts`、`src/engine/effects.ts`、`src/engine/patches.ts`、`src/engine/automation.ts`、`src/engine/ducking.ts`、`src/engine/clip.ts`、`src/engine/clip-worklet.ts`、`src/engine/tuning.ts`、`src/params/mixer.ts`
関係するテスト: `tests/playback/sound.test.ts`

## 振る舞い

### 音の経路

```
kick, snare, hat, ghost（サンプラー）─▶ トリム ─▶ ch ─▶ ドラムバス（Comp）─┐
sub   ─▶ Distortion ─▶ LPF(100) ─▶ [イントロ LPF] ─▶ [ダッキング] ─▶ トリム ─▶ ch ─┤
reese（音色ごとに1台）─▶ HPF(120) ─▶ [イントロ LPF] ─▶ [ダッキング] ─▶ トリム ─▶ ch ─┤
stab（音色ごとに1台）─▶ LPF(3k) ─▶ [イントロ LPF] ─▶ トリム ─▶ ch ──────────────┤
pad（音色ごとに1台）─▶ LPF(1.5k) ─▶ [イントロ LPF] ─▶ [パッドのゲート] ─▶ [ダッキング] ─▶ トリム ─▶ ch ─┤
riser: Noise ─▶ BPF ─▶ Gain ─▶ fx のトリム ─▶ ch ────────────────────────────────┤
impact: MembraneSynth + NoiseSynth ─▶ HPF(80) ─▶ fx のトリム ─▶ ch ────────────────┤
  ch のセンド ──────────────────────────▶ リバーブ ─▶ リターンの ch ────────────────┤
  snare のトリム ─▶ [スローのゲート] ─▶ [スローの送り量] ─▶ リバーブ               │
                                                                                     ▼
ミックスバス ─┬▶ [スイープ HPF] ─▶ [× 割合] ──────┬▶ マスター（Comp ─▶ Limiter）─▶ クリップ検出 ─▶ ゲート ─┬▶ 音量 ─▶ 出力
              └▶ HPF(20) ────────▶ [× (1 − 割合)] ─┘                                                      └▶ Analyser（FFT）
```

`ch` はミキサーのチャンネル（音量・パン・ミュート・ソロ）で、センドは音量の後から取ります。

### ミキサー

| チャンネル | パン | センド | ソロ |
| --- | --- | --- | --- |
| キック | — | — | ○ |
| スネア・ハイハット・ゴースト | ○ | ○ | ○ |
| サブベース | — | — | ○ |
| リースベース・スタブ・パッド・FX | ○ | ○ | ○ |
| リバーブのリターン | — | — | — |

| 項目 | 範囲 | 表示 |
| --- | --- | --- |
| 音量 | −40〜+6 dB の整数 | dB |
| パン | −1〜1 | L100〜C〜R100 |
| センド | 0〜1 | 百分率 |
| ミュート・ソロ | オン・オフ | — |

既定値は `config.example.json` の `mixer` にあります。ミキサーの操作は即時に、50 ms で滑らかに効きます。

**ソロ**

| 状態 | 鳴るか |
| --- | --- |
| どのチャンネルもソロでない | ミュートでなければ鳴る |
| 1つ以上のチャンネルがソロ | ソロで、かつミュートでないチャンネルだけが鳴る |
| リバーブのリターン | ソロの有無によらず、ミュートでなければ鳴る |

ソロは複数のチャンネルに同時にかけられ、ミュートはソロより優先します。鳴らないチャンネルはリバーブへのセンドも止まり、スネアが鳴らないときはリバーブスローも止まります。リバーブスローはスネアのフェーダーの位置には従いません。

### ダッキング

実際に鳴るキックごとに、サブベース・リースベース・パッドの音量を下げます。

- キックの瞬間に `1 − ダッキング量 × パートの比` まで下げきり、戻り時間をかけて1に戻す。下げ始めはキックの 3 ms 前
- 戻りきる前に次のキックが来たら、その時点の値から下げ直す
- キックを消すフィルの間や、キックを抜いたシーンでは下げない

ダッキング量と戻り時間はパラメーター（`ducking.depth`・`ducking.release`、30〜300 ms）で、次の2bar の予約から効きます。パートの比は `sound.duckRatio` です。

### ダイナミクスとクリップの検出

- ドラム4パートをまとめるドラムバスにコンプレッサー、マスターにコンプレッサーと最終段のリミッターを置く。値は `sound.dynamics`
- リミッターの後で、全サンプルのピークと、0 dBFS 以上のサンプルの数を数え、約0.1秒ごとに画面のピークメーターとクリップの回数に送る。回数は停止から再生したときだけ0に戻す
- 聴く音量（`volume`）はクリップの検出とゲートの後に置く

### 音色

リースベース・スタブ・パッドは、音色ごとにシンセを1台ずつ持ちます。どの音色を使うかはサイクルごとに決まります（[アレンジ](../generation/arrangement.md#音色)）。

| --- | --- | --- | --- | --- | --- | --- |
| `classic` | fatsawtooth、3本、25 セント | 2 | 0.01 / 0.25 / 0.3 / 0.1、200 Hz、3 | 0.005 / 0.2 / 0.8 / 0.05 | 0 dB | うなりのある標準的なリース |
| `wide` | fatsawtooth、5本、40 セント | 1 | 0.02 / 0.4 / 0.5 / 0.1、300 Hz、2.5 | 0.005 / 0.3 / 0.9 / 0.05 | −2 dB | 本数とデチューンを増やした、広く滑らかなリース |
| `hollow` | fatsquare、3本、20 セント | 4 | 0.01 / 0.2 / 0.2 / 0.1、250 Hz、2 | 0.005 / 0.15 / 0.8 / 0.05 | −5 dB | 矩形波の奇数倍音とレゾナンスで、鼻にかかったニューロ寄りの音 |

**サブベース**: サイン波の `Tone.Synth` に弱い `Tone.Distortion` をかけ、100 Hz・−24 dB/oct のローパス（Q 0.7）を通します。

**音色の制約**: 全音色がこれを満たすことを単体テストで確かめます。

| 制約 | 値 | 根拠 |
| --- | --- | --- |
| パッドのアタック | パッドのゲートが開く時間（0.4 秒）以上 | 溜めの後のゲートのランプで、ドロップの頭の和音の立ち上がりが鈍らないようにする |
| パッドのリリース | 1.2 秒以下 | 2bar ごとに鳴らし直す4音の和音が、前の和音のリリースと2つ重なる見積もりで、同時発音数（12）を決めている |
| スタブのリリース | 0.15 秒以下 | 2ステップ間隔のスタブが3〜4つ重なる見積もりで、同時発音数（12）を決めている |
| 重ねるオシレーターの数 | リース5本、スタブ・パッド3本まで | 型（`FatOscillator<C>`）で表す。FM 系は1音あたり2つ |
| 補正 | 0 dB 以下 | 下の「決定理由」 |
| FM の比 | 1以上の整数 | 下の「決定理由」 |

### FX の鳴り方

| FX | 鳴り方 |
| --- | --- |
| ライザー | 音量は進み具合 `p` に対して `peakGain × p²`、中心周波数は `lowHz` から `highHz` へ対数で補間する。止まる位置で 10 ms で音量を0にする |
| ハイパスのスイープ | `openHz` から `closedHz` へ対数で上げる。ドロップの頭で 5 ms かけて開いたままの側に受け渡す |
| ローパスのスイープ | 効果の始まりで 20 ms かけて `closedHz` まで閉じてから、`openHz` へ対数で開く |
| インパクト | ブームは `Tone.MembraneSynth`（G2 から下がる）、バーストは `Tone.NoiseSynth`。80 Hz のハイパスを通す。音量は `sound.fx.impactVolumeDb` |
| リバーブスロー | 打音の 5 ms 前に送り量を上げ、120 ms 後に0に戻す |
| パッドのゲート | 溜め（`cut`）の頭で 30 ms で閉じ、2bar の終わりから 0.4 秒で開く |

周波数の範囲・ライザーの最大音量・スローの送り量の既定値は `sound.fx` にあります。

## 実装

### `Instruments`（`engine/audio.ts`）

トランスポートが使う窓口です。`loadInstruments(drumSamplesUrl, mixer, sound)` が経路を組み立てて返します。

| メソッド | 役割 |
| --- | --- |
| `drum`・`sub`・`reese`・`chord` | 発音の予約。`reese` と `chord` は音色を受け取り、その音色のシンセに送る |
| `open(time, resumed?)` | 新しいシンセ・サンプラー・リバーブを用意し、オートメーションを休止の値にしてから、`resumed` があれば再開位置の値を同じ時刻に設定し、ゲートを 10 ms で開く |
| `silence(time)` | ゲートを 10 ms で閉じ、サンプラーとシンセを解放し、ダッキングとオートメーションの予約を消して休止の値に戻す |
| `setVolume`・`setMixer` | 聴く音量とミキサー |
| `duck(kicks, ducking)` | 2bar 分のダッキングを、前の2bar から続けて予約する |
| `fx(events, pairStart, stepSeconds, from?)` | オートメーションの点列とインパクトを予約する |
| `onLevel(listener)` | ピークとクリップの計数を受け取る |
| `spectrum()` | FFT の各ビンの dB 値とサンプリング周波数 |

### チャンネルとフェーダー（`engine/strips.ts`）

- 鳴らないチャンネル（ミュートかソロで外れた）は、フェーダーを −∞ dB にする。センドはチャンネルの後から取るので、センドも止まる
- 各チャンネルは前回の設定と鳴るかどうかを覚え、変わったパラメーターだけを動かす
- フェーダー・パン・センドと、聴く音量、スローのゲートは `glide` で動かす。オーディオの現在時刻から 50 ms の直線のランプを置き、ランプが終わったらもう一度、現在時刻で目標の値を設定する。再生を一度も始めていない（AudioContext が止まっている）ときは、すぐに設定する

### 音源（`engine/voices.ts`）

- ドラムは `Tone.Sampler` で、各サンプルを1つのノートに割り当て、元の音高のまま鳴らす。バッファは起動時に一度だけ読み、サンプラーは `open` のたびにバッファから作り直す
- 音程のあるパートのシンセとインパクトは、`open` のたびに作り直す
- ノートの長さは `length × 16分の秒数` から 5 ms 短くして予約する
- スタブとパッドの `PolySynth` の同時発音数は 12

### 鳴り終えたオシレーターの解放（`engine/oscillator-release.ts`）

Tone.js の `Oscillator` は、前の音が鳴り終えた後に次の音を始めるたびに新しいネイティブの `OscillatorNode` を作り、自分の `frequency` と `detune` の信号をその AudioParam につなぎますが、このつながりを切りません。起動のとき（`boot` で AudioContext を作る前）に `Tone.Oscillator.prototype._start` を包み、作ったノードが鳴り終えたら、信号をそのノードの AudioParam から切ります。

- 渡すのはノードのネイティブの AudioParam（`param.input`）。Tone.js の `Param` を渡すと、信号のつながりをすべて切ってしまう
- シンセを破棄した後に鳴り終えたノードでは何もしない。破棄で信号のつながりはすでに消えている
- 2回入れても1回だけ包む
- Tone.js の版は `15.1.22` に固定する

### 鳴り終えた音源の破棄（`engine/source-disposal.ts`）

Tone.js は、音ごとのオシレーターとバッファ音源（`OneShotSource`）を、鳴り終えた後に `requestIdleCallback` で破棄します。起動のとき（`boot` で AudioContext を作る前）に `OneShotSource.prototype._onended` を包み、呼んでいる間だけ `window.requestIdleCallback` を `undefined` にして、Tone.js の代わりの道（`setTimeout(dispose, 10)`）で破棄させます。

- 呼んだ後は `requestIdleCallback` を元に戻す
- 入れるときに、`ToneOscillatorNode` と `ToneBufferSource` が同じ基底を持ち、`_onended` が関数であることを確かめ、違えば例外を投げる
- 2回入れても1回だけ包む



### ダッキング（`engine/ducking.ts`）

```ts
interface Dip { kick: Seconds; floor: number; release: Seconds }
function duckPoints(kicks: readonly Seconds[], carry: Dip | null, shape: { floor: number; release: Seconds })
  : { points: readonly { time: Seconds; gain: number }[]; last: Dip | null };
```

1つのキックにつき、`(kick − 3 ms, その時刻のゲイン)`、`(kick, floor)`、`(kick + release, 1)` の3点を作ります。次のキックが戻りきるより早ければ、3点目の代わりに `(次のキック − 3 ms, その時刻のゲイン)` を置き、値は戻りの途中を直線で補間して求めます。2bar をまたぐ戻りは、前の2bar の最後のキック（`carry`）から求めます。エンジンは、最初の点の時刻で予約を取り消してから、点を `linearRampToValueAtTime` で並べます。

### クリップの検出（`engine/clip.ts`、`engine/clip-worklet.ts`）

リミッターの後に AudioWorklet を挟み、入力をそのまま出力へ流しながら、全サンプルの絶対値の最大と、絶対値が1以上のサンプルの数を数えます。数える処理は `scanBlock(samples, tally)` として切り出し、単体テストで直接呼びます。

### オートメーション（`engine/automation.ts`、`engine/effects.ts`）

```ts
type AutomationTarget = 'riserGain' | 'riserFrequency' | 'highpass' | 'highpassShare' | 'lowpass' | 'throwSend' | 'padGate';
interface AutomationPoint { target: AutomationTarget; time: Seconds; value: number; ramp: 'set' | 'linear' | 'exponential' }
function fxAutomation(events, pairStart, stepSeconds, fx: FxTuning, from: Step = 0): readonly AutomationPoint[];
function fxStateAt(events, step, stepSeconds, fx: FxTuning): AutomationValues;
function restingValue(fx: FxTuning): AutomationValues;
```

`highpassShare` は、ミックスのうちスイープするハイパスを通す割合です。`effects.ts` の `automate` が、ターゲットごとのパラメーターに点を適用し、休止の値に戻し（`rest`）、再開位置の値を一度に設定します（`setAll`）。

| FX | 点 |
| --- | --- |
| ライザー | 効果の始まる2bar（`startProgress` が0）だけ、2bar の頭で開始時の値に `set`。区間の終わりで終了時の値へ。音量は `linear`、周波数は `exponential`。`endProgress` が1なら、10 ms 後に音量を0へ `linear` |
| ハイパスのスイープ | 効果の始まる2bar だけ、頭で開始時の周波数に `set` し、区間の終わりへ `exponential`。同じ2bar の頭で割合を0に `set` し、5 ms で1へ `linear`（両方のハイパスが開いているので聞こえない） |
| ローパスのスイープ | 効果の始まる2bar だけ、頭で開いた周波数に `set` し、20 ms で閉じた周波数へ `exponential` してから区間の終わりへ |
| フィルターのリセット | 2bar の終わりの 5 ms 前に割合を1に `set` し、終わりで0へ `linear`。終わりで、ハイパスとローパスを開いた周波数に `set`。同じ瞬間に終わるハイパスのランプより後に予約する |
| リバーブスロー | 打音の 5 ms 前に送り量を `set`、120 ms 後に0へ `set` |
| 溜め | `cut` のとき、開始で1に `set`、30 ms でゲートを0へ `linear`。2bar の終わりで0に `set` し、0.4 秒で1へ `linear`。`held` では点を作らない |

2bar をまたいで続く効果は、続きの2bar で値を `set` し直さずランプだけを足します。境界で値を変える点（フィルターのリセット）は、境界で終わるランプと同じ2bar から求めます。

### 再開位置の値

`fxStateAt` は、その2bar の FX のイベントだけから、一時停止しなかった場合にステップ `step` の時刻で各パラメーターが取る値を返します。続いている効果は、どの2bar にも開始と終了の進み具合を持つ区間として出ているので、前の2bar を参照せずに済みます。

| パラメーター | 値 |
| --- | --- |
| ライザーの音量 | 区間内なら、両端の値を `step / to` で直線補間（Web Audio の直線のランプと同じ形）。区間の後で `endProgress = 1` なら 0 |
| ライザーの周波数、ハイパス、ローパス | 区間内なら、両端の周波数を `step / to` で対数補間（指数のランプと同じ形）。区間の後は終わりの値 |
| ハイパス側の割合 | ハイパスのスイープの区間がある2bar では 1、ない2bar では 0 |
| リバーブスローの送り量 | スローの打音の 5 ms 前から 120 ms 後までにステップの頭があれば送り量、なければ 0 |
| パッドのゲート | `cut` の溜めで `step > from` なら 0、それ以外は 1 |
| ほか | 休止の値（`restingValue`） |

`fxAutomation` に `from > 0` を渡すと、効果の始まりの点を作らず、ステップ `from` より前の点を除きます。残るランプは、`open` が再開の時刻に設定した値から、一時停止しなかった場合と同じ終点に向かうので、曲線も一致します。

### スペクトラムアナライザーの取り出し

ゲートの出力から `Tone.Analyser({ type: 'fft', size: 4096, smoothing: 0.6 })` に分けます。画面は Tone.js を読まず、`spectrum()` が返す値だけから描きます（[画面](../interface/screen.md#スペクトラムアナライザー)）。

## 決定理由

- **出力の直前にゲートを置く**: 先読みで予約済みの音は Transport を止めても鳴り続けるので、停止と一時停止で確実に切るため。最後に置くので、リバーブの残響も切れる。ゲートを一気に開閉せず 10 ms のランプにするのは、途中まで上がったライザーを再開するときなどにクリックを出さないため
- **シンセ・サンプラー・リバーブを `open` のたびに作り直す**: 前の再生で予約した音がシンセの予定に残り、ゲートを開くとモノフォニックのシンセの1音の上で新しい音とぶつかったり、ポリフォニーのボイスを使ったままにしたりするため。サンプラーは、一時停止の直後（同じ2bar の残りのうち）に再開されるのが普通で、`releaseAll` はまだ始まっていない予約をタイマーから止めるので、タイマーが遅れると古い打音が再開後に鳴る。作り直せばタイマーの都合によらず消せる。リバーブは前の残響を持ち越さないため。インパルス応答を非同期に作るが、待たずに始める（最初の数十 ms が乾いて鳴るだけ）
- **ノートを少し短く予約する**: モノフォニックのシンセでは、リリースと次のアタックが同じ時刻に重なると、クリックが出たり次の音が落ちたりするため
- **サブベースに弱い歪みとローパスをかける**: サイン波だけでは倍音がなく、小さいスピーカーでは音高が聴き取れないため。ローパスは基本の音域（82 Hz まで）を残し、跳躍した音と歪みの倍音を抑える。キックと同じ程度の音量にすると、跳躍した音だけが浮いて聞こえた。小さいスピーカーで音高を伝える役割は、中域のリースベースに任せる
- **音源のトリムでパート間の音量差をそろえる**: ミキサーの音量を 0 dB から始められるようにするため。ドラムは単体でもフルスケールに達し、リミッターに余裕がなかった。サブベースは、試聴でフェーダーを −6 dB にしたときにキックとリースベースと釣り合ったので、トリムに移した
- **キックとサブベースにパンとセンドを持たせない**: 低域をモノラルに保ち、リバーブで低域を濁らせないため
- **ダッキングをキックのイベントから予約する**: Tone.Compressor にはサイドチェインの入力がないため。キックの時刻は2bar 分前もって分かるので、キックの瞬間に下げきっておける。少し前から下げ始めるのは、キックの頭とベースの立ち上がりが重ならないようにするため。点列を Tone.js から切り離すのは、Node.js 上で単体テストするため
- **クリップを全サンプルで数える**: Tone.Limiter はレシオ20・アタック3ms のコンプレッサーで、ブリックウォールリミッターではないので、速い立ち上がりで 0 dBFS を超える可能性が残る。平滑化した値を画面の更新周期で読むと短いピークを見逃し、タブが背景にあると更新自体が間引かれる。AudioWorklet に出力を持たせて経路に挟むのは、出力先のない AudioWorkletNode が処理されるかどうかがブラウザによって異なるため
- **聴く音量をクリップの検出の後に置く**: 聴く音量を下げても、クリップの検出とスペクトラムの表示が変わらないようにするため
- **フェーダーを現在時刻から動かし、終わったら設定し直す**: Chrome（Brave 155 で確認）は、現在時刻より先に予約した値を適用しないことがあり、ソロで鳴らないはずのパートが次の操作まで鳴り続けた。現在時刻で設定した値は、確かめたかぎり必ず適用された。Tone.js の `rampTo` と `mute` は先に予約するだけなので使わない。ミキサーの操作は拍に合わせる必要がないので、先読みの分だけ遅らせない。50 ms は、すぐに効いたと感じられ、クリックが出ない長さ
- **Tone.js のソロを使わない**: 同時に1つしかソロにできず、リバーブのリターンのチャンネルまで消すため。ソロでないチャンネルのセンドも止めるのは、ソロにしたパートの残響だけを聴けるようにするため
- **スネアが鳴らないときにスローも止める**: ほかのパートをソロにしているのにスネアの残響だけが聞こえると、故障に見えるため。スローは別の `Gain` で止め、送り量のオートメーションとミキサーが同じパラメーターを取り合わないようにする
- **FX のオートメーションでミキサーの設定を書き換えない**: スローは通常のセンドとは別の経路で送り、スイープはミキサーの外のフィルターを動かす。ミキサーの操作とオートメーションが同じ値を取り合わないようにするため
- **ビルドのハイパスを2本並べて割合で受け渡す**: 1本のフィルターの周波数を音が流れているうちに飛ばすと、フィルターの内部の状態が、元の音よりはるかに大きな低域の衝撃になって出てくる。溜めのない入り方やパッドを残す入り方では、ドロップの頭でこの衝撃がリミッターを越えてクリップしていた。ドロップの頭では 5 ms で開いたままの側に受け渡してから、聞こえなくなったスイープ側の周波数を戻す。開いたままの側を素通しにせず 20 Hz のハイパスにするのは、低域の鳴り方（サブベースの最低音域が 1〜2 dB 持ち上がる）を変えないため。2本の割合は1つの信号から作り、合計が常に1になるようにする
- **ローパスを 20 ms かけて閉じる**: 一気に閉じると、前のドロップの残りが流れているところで衝撃が出るため
- **イントロのローパスを音程のあるパートごとに、チャンネルより前に置く**: リバーブへの送りにもかけるため。サブベースは自身のローパスがその範囲より下にあるので実質的には変わらないが、4パートにそろえる
- **パッドのゲートをダッキングとは別の Gain にする**: ダッキングの予約と同じパラメーターを取り合わないため
- **溜めの後でゲートを 0.4 秒かけて開く**: すぐに開くと、溜めで切ったパッドのリリースがドロップの頭で聞こえ直すため。再開したときは、その余韻がないので、開いた状態から始める
- **ライザーのノイズを鳴らしっぱなしにする**: ビルドのたびに起動と停止を予約するより、止めるときに音量のパラメーターの予約を消すだけで済むため
- **インパクトを 80 Hz のハイパスに通し、シンセ自身の音量で下げる**: ドロップの頭でキックとサブベースに低域を重ねず、リミッターの手前で振幅が積み上がらないようにするため。FX のチャンネルのトリムで下げると、同じチャンネルのライザーまで下がる。試聴で前に出すぎていたので下げた
- **2bar の境界で値を設定し直さない**: 2bar ごとの開始時刻はトランスポートが別々に求めるので、浮動小数の誤差で前の2bar の終わりと僅かに前後する。次の2bar の頭の点が前のランプの終わりより前に入ると、Web Audio はそのランプの起点をその点とみなし、ランプ全体が崩れるため
- **周波数を `exponentialRampToValueAtTime` で動かす**: 2点の間を対数で補間するので、耳に一定の速さに聞こえる。ライザーの音量は 0 に向けた指数のランプが使えないので直線にする
- **音色ごとにシンセを持ち、送り先だけを切り替える**: 切り替えの予約が要らず、前のサイクルの余韻は前の音色のシンセでリリースまで鳴りきる。鳴っていないシンセはオシレーターを止めているので、負荷はほとんど増えない（増えるのはノードの数とメモリだけ）。イントロのローパス・ダッキング・パッドのゲート・チャンネルはパートの入力より後ろにあるので、どの音色にも同じようにかかり、音色を替えてもミキサーの意味が変わらない
  - 不採用の方式: 鳴っているシンセの設定を書き換える（`PolySynth.set()` はリリース中の声にもかかり、余韻の音色が途中で変わる。オシレーターの種類を替えると作り直されてクリックが出る）。シンセを2台持って交互に使う（使っていない側を再生中に作り直すことになり、管理も要る。全音色で10台なので、再生中にノードを作らず送り先を選ぶだけの方を採る）
- **音色の表をシンセの設定の唯一の置き場にする**: 表と生成のコードを二重に持つと、制約のテストが実際に鳴る音を確かめなくなるため。`Record<名前, 設定>` にするので、名前を足して設定を書き忘れると型エラーになる
- **FM の変調波を正弦波にする**: Tone.js の既定は矩形波で、どの FM の音色も荒く濁るため
- **FM の比を1以上の整数にする**: 1未満や非整数にすると、側波帯が基音の下や倍音列の外に出て、音高が1オクターブ下に聞こえたり、和音が濁ったりする。リースの音高がサブベースの帯域に聞こえると、ハイパスで分けた意味がなくなる
- **音色の補正を 0 dB 以下にする**: トリムとリミッターの余裕は、表の先頭の音色で測ったもの。補正をプラスにすると、クリップしない保証が崩れる。補正は、パートの共通のフィルターを通してオフラインで鳴らした実効値を、先頭の音色にそろえた値で、試聴で確定した。Tone.js は fat 系のオシレーターを重ねる数で割り、FM 系はそのままの振幅で鳴らすので、FM の音色ほど大きく下げている。`pluck` は補正ではなくディケイを長くして差を縮めた
- **鳴り終えたオシレーターから信号を切る**: standardized-audio-context はつながりを送り元の `outputs` に記録し、送り元を `disconnect` したときにだけ消す。信号はシンセと同じだけ生きる（`open` から次の `open` まで）ので、記録が鳴り終えたオシレーターをすべて保持し、再生を続けるほどメモリが増えた。デチューンで重ねた音色は本数分、FM の音色は2つずつ溜まる。Tone.js の最新版（15.5.57）でも直っていない
- **Tone.js の内部を包み、自前の音源やシンセの作り直しで避けない**: アプリの音源の形を変えずに直せるため。オシレーターを鳴らし続けて音量だけで音を出す自前の音源にすると、音の頭の位相が毎回変わり、アタックの聞こえ方が変わる。シンセを定期的に作り直すと、鳴っている音の余韻が切れる
- **破棄の後と2回目の切断を避ける**: どちらも `InvalidAccessError` を投げる。Tone.js のタイムアウトは、例外を投げたコールバックを取り除かずに毎回呼び直し、後のタイムアウト（ほかの音源の終わりの処理を含む）もすべて止まるため
- **鳴り終えた音源を `setTimeout` で破棄させる**: Chrome は隠したタブでアイドル時間のコールバックを実行しないので、破棄の待ちが音の数だけ溜まり、それぞれが音源とそのゲイン・AudioParam を保持した（30 分で約3万件、ヒープは 200 MB 近く）。`setTimeout` は隠したタブでも実行される（間引かれても約1秒ごと。音を鳴らしているページは強い間引きの対象外）。Tone.js が `requestIdleCallback` のないブラウザのために用意している道なので、破棄の処理そのものは変えずに済む
- **`requestIdleCallback` にタイムアウトを足す案を採らない**: 隠したタブでタイムアウトが実行されるかを、自動の確認では確かめられないため（ヘッドレスのブラウザはタブを隠しても `visible` のまま）
- **`requestIdleCallback` を音源の終わりの処理の中だけで隠す**: ページ全体で差し替えると、ほかのコードの振る舞いまで変わるため。Tone.js のタイムアウト（`context.setTimeout`）を使わないのは、例外を投げたコールバックがそのループのほかのタイムアウトをすべて止めるため
- **Tone.js の版を固定する**: 包むのは型に出ていない内部（`_start`・`_oscillator`）で、版が変わると黙って効かなくなったり壊れたりするため。上げるときは、アプリを読まないページで各音源に間を空けた音を鳴らし、GC の後に生きている `OscillatorNode` の数が今鳴っている分だけであることを確かめ直す（[テスト](../quality/testing.md#e2e-テスト)）
- **同時発音数を 12 にする**: `PolySynth` は予約した音のボイスを先読みの分だけ早く確保し、オシレーターの停止の知らせがメインスレッドに届くまで空けない。スタブは2ステップ間隔で鳴ると3〜4回分が重なり、パッドはリリースが次の和音と重なる。8では音が落ちた。使っていないボイスは自動で破棄されるので、普段の負荷は増えない。音色ごとにシンセを分けるので、前の音色の余韻が新しい音色の発音数を使うことはない
