# ロードマップ

## 全体像

ドラムのみの MVP で「変化の作法」を固め、その上にベース、ウワモノ、FX とアレンジを順に重ね、最後に和声を充実させて操作と表示を整えます。各ゲートの完了条件を満たしてから次のフェーズに進みます。

フェーズ0の後のゲートだけは、受け入れ基準に加えて変化率の確定を条件にしています。

## フェーズ詳細

各フェーズは前フェーズの完了条件を満たしてから着手します。フェーズ0と1の間には、試聴とシミュレーションで変化率を詰める調整期間を必ず設けます。ここで決めた変化の作法が、後から加わる全パートの基準になるためです。

### フェーズ0: MVP（ドラムのみ）

- ドラム4パート、2bar 基本パターン、8bar 境界の変異、装飾、フィル
- シード付き乱数、Tone.js の Transport による再生、最小 UI、シミュレーションツール
- **完了条件**: MVP要件定義書の受け入れ基準をすべて満たす

### フェーズ1: 32bar 構造とベース

- 32bar の区間の関係（反復・変奏・転換・変奏）と、32bar 境界での強い変異・大きなフィル
- 32bar 単位のエネルギーカーブ（密度のマクロ制御）
- 固定キーのサブベース。リズムはキックからの派生を基本とし、キックと独立な型も持つ
- **完了条件**: 30分の試聴で32bar の区切りを指摘できる

### フェーズ2: ハーモニー、ウワモノとミックス

- コンダクターにコード進行の生成を追加（8bar で4コードの進行。2bar ごとにコードが変わる）
- リースベース、スタブ、パッドの合成音源（Tone.js のシンセで構成）
- パート別ミキサー（音量・パン・ミュート）と、センド/リターン構成のリバーブ（Tone.Reverb）
- ドラムバス・マスターのコンプレッサー（Tone.Compressor）と、最終段のリミッター（Tone.Limiter）
- キックをトリガーにしたサイドチェインでベースとパッドをダッキング。Tone.Compressor にはサイドチェイン入力がないため、キックのイベントから Tone.Gain のゲインエンベロープを予約して模擬する
- **完了条件**: 調性の破綻がなく、ベースとキックの低域がぶつからず、全パート同時再生で音割れや処理落ちがない

### フェーズ3: FX とアレンジ

- ライザー、インパクト、リバーブスロー、フィルタースイープのオートメーション
- シーン（イントロ・ビルド・ドロップ・ブレイクダウン）を、128〜192bar（32bar 単位で変動）のサイクルで巡回させるアレンジ層。サイクル内では主題（主進行とフレーズ）を共有し、イントロはサイクルごとに戻す
- **完了条件**: 1時間の試聴で展開の起伏を感じ、シーンの切り替わりが自然に聞こえる

### フェーズ4: 和声の拡充と UI の簡素化

- 一時停止と再開。再開すると止めた位置の続きから鳴らす
- テンションやモーダルインターチェンジ（借用和音）を織り込み、コード進行を充実させる
- 位置の文字表示からキー・コード・シーン・フェーズなどを削り、累計小節数と累計サイクル数の数値だけにする
- 位置メーターを「サイクル内の8bar」と「8bar 内の2bar」の2行に絞り、ラベルを削る。シーケンサーが2bar 単位で表示するので、小節単位のメーターは要らない
- シーケンサーと、セグメントメーター型のスペクトラムアナライザー（周波数バー）を切り替えて、同じ場所にどちらか一方だけを表示する
- ミキサーを初期画面から外す。別メニューにするか、シーケンサー・スペクトラムアナライザーとの3つの切り替えにするかは要件定義で決める
- ミキサーにソロボタンを追加する
- パラメーターを隠せるようにし、初期画面では隠しておく
- シーケンサーでスネアとゴーストスネアを同じレーンに並べる
- クエリ文字列で初期シードを指定できるようにする
- パラメーターとミキサーの初期値、生成と音の調整用の数値を、設定ファイル（JSON）で上書きできるようにする。ファイルやキーがなければコードの既定値を使う
- シードを含めるかを選んで、ページの URL を共有できるようにする
- メディアキーや OS のメディア操作（ロック画面、通知）から再生・一時停止・停止できるようにする（Media Session API）
- 幅の狭い画面（スマートフォンの縦向き）でも、はみ出さずに全体を表示する
- **完了条件**: 初期画面に再生操作・累計表示・位置メーターと、シーケンサーかスペクトラムアナライザーのどちらかだけが並ぶ。一時停止から再開しても止めた位置から途切れずに続く。1時間の試聴でテンションや借用和音が調性を崩さず、ベースとも濁らない

## リスクと対策

| リスク | 影響するフェーズ | 対策 |
| --- | --- | --- |
| 変化率の調整が主観に頼り、収束しない | 0〜1 | シミュレーションで密度・反復率を数値化し、試聴は評価シートで記録する |
| ブラウザのタブ非表示時にタイマーが間引かれ、音が途切れる | 0 | Tone.js の Worker クロックと十分な lookAhead を使い、早い段階で各ブラウザで検証する |
| 合成音源を増やすと CPU 負荷で音切れが起きる | 2〜3 | パートごとの負荷を計測し、重い音はサンプル化やボイス数制限で対処する |
| Tone.js（Web Audio）に本物のサイドチェインがなく、ダッキングが不自然 | 2 | キックのイベントからゲインエンベロープを予約する方式で、カーブを調整可能にする |
| パートを足すと全体のまとまりが崩れる | 1〜3 | 全パートがコンダクターのコンテキストだけを参照し、境界のタイミングを共有する |
| ドラムサンプルのライセンス問題 | 0, 4 | 自作またはライセンスが明確な素材に限定し、出典を記録する |
| テンションや借用和音がベースとぶつかり、調性が濁る | 4 | テンションは上モノに限り、ベースはコードの根音と構成音を保つ。借用元は同主調など近い調に限る |
| 一時停止をまたぐと、予約済みのオートメーション（ライザー、フィルタースイープ、ダッキング）や残響が途切れたり残ったりする | 4 | 再開時に位置からオートメーションの値を復元し、シーンの境界をまたぐ一時停止を試験で確かめる |
| スペクトラムアナライザーの描画で CPU 負荷が増え、音切れが起きる | 4 | 描画を表示中だけ画面の更新に合わせて行い、FFT のサイズを抑える |
