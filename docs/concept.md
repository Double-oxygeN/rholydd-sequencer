# 考え方

Rholydd Sequencer が何を目指し、どういう考え方で「聴ける」音楽を生成しているか、何を扱わないかをまとめます。個々の規則は、[生成](./generation/) の各文書に書きます。

## 目的

パラメーターを選んで再生を押すだけで、ドラムンベースを止めるまで鳴らし続けるブラウザのアプリです。1時間聴き続けても、同じループの繰り返しにも、無秩序にも聞こえないことを目指します。

- **途切れずに鳴り続ける**: 2bar ずつ先読みして生成し、終わりのない1曲として鳴らす
- **まとまりのある展開**: 2bar・8bar・32bar・サイクルのそれぞれの単位で、変えてよいものと変える時期を決める。完全なランダムにはしない
- **DnB の文法を崩さない**: ステップごとの重み表とパートごとの変わりやすさで、乱数で作ってもジャンルの形を保つ
- **再現できる**: 同じシード・パラメーター・設定ファイルなら、同じ展開をもう一度聴ける
- **聴く道具として邪魔をしない**: 初期画面は再生の操作と、位置とビートを見る表示だけにする

## 変化の作法

「何を変えるか」より「いつ、どのくらいの期間だけ変えるか」を階層ごとに分けることが、聴いていて飽きないビートを作る鍵です。

### 3種類の変化

| 種類 | 効果の期間 | 例 |
| --- | --- | --- |
| 装飾（一時変化） | その2bar の中だけ。終わると元に戻る | ゴーストスネア、ハイハットの追加 |
| 変異（持続変化） | 境界でパターンを書き換え、以降の基準になる | キックの位置の変更 |
| フィル（予告変化） | 区切りの終わりで次の境界を知らせる | スネアロール、ドロップアウト |

### 階層ごとの役割

| 階層 | 構成 | 境界での変化 | 終わりの扱い |
| --- | --- | --- | --- |
| 2bar（基本ループ） | 16分×32ステップ。1小節目が問い、2小節目が答え | なし（装飾だけ） | 2小節目の後半に軽い装飾 |
| 8bar（セクション） | 2bar×4。反復・反復・反復・変奏 | 弱い変異（基準からの変奏） | 8小節目の終わりに短いフィル |
| 32bar（フレーズ） | 8bar×4。A（反復）・A'（変奏）・B（転換）・A''（変奏） | 強い変異（基準パターンの書き換え） | 31〜32小節目に大きなフィル |
| サイクル（1曲） | 32bar×4〜6。イントロ・ビルド・ドロップ・ブレイクダウン | 主題・グルーヴ・キー・音色の入れ替え | ドロップ2の大きなフィルから次のイントロへ |

### 反復の作り方

ランダムさは「シード＋区間の関係」から決定的に導きます。各区間は、その階層の基準となる区間に対して「反復」（同じ形）、「変奏」（少しだけ違う形）、「転換」（まったく違う形）のいずれかの関係を持ちます。反復の箇所では同じ装飾まで再現されるので繰り返しが聴き取れ、その上の変奏や転換が「展開」として聞こえます。

変奏と転換は毎回基準から作り直し、累積させません。A に戻る感覚（A A' B A''）で32bar のまとまりを聴き取れるようにするためです。長い時間の展開は、32bar とサイクルの境界での強い変化が担います。

## 聴かせどころと緩急

パターンが無限に生成され続けると、どの瞬間も同じくらい「それなり」に聞こえ、山も谷もない状態に陥りやすくなります。そこで、次の5つの原則で起伏を作ります。

1. **対比で山を作る**: ドロップの迫力は、ドロップ自体の密度よりも、直前のブレイクダウンやビルドとの落差で決まる。ブレイクダウンではキック・スネア・ベースを抜き、ハイハットと和声だけに絞る
2. **期待を溜めてから解放する**: ビルドでは低域を抜き、ライザーとハイパスで緊張を上げ続け、ドロップの直前で溜める。ドロップの頭でインパクト・キック・サブベースを同時に戻し、溜めた期待を一気に解放する。溜めの形（ドロップの入り方）はドロップごとに変え、毎回同じ1拍の無音には頼らない
3. **戻ってきた主題で聴かせる**: 2回目のドロップでは、1回目と同じ進行・ベースライン・スタブが戻ってくる。聴き覚えのあるものが戻る瞬間が、生成音楽で最も「聴かせどころ」として認識されやすいため。ドラムのグルーヴだけは変え、同じものの繰り返しには聞こえないようにする
4. **サイクルを1曲として区切る**: サイクルの中では主題を共有して統一感を持たせ、サイクルの頭で主題・グルーヴ・音色を入れ替え、ときにはキーも近親調に移す。イントロはサイクルごとに戻し、薄いビートとこもったパッドから始め直す。最初の8bar に鳴らすドラムとパートが入る順（イントロの入り順）もサイクルごとに替え、曲が替わったことをイントロの入りからも伝える。ドラムは途切れさせず、DJ ミックスで次の曲のイントロにつなぐように聞かせる
5. **周期をずらす**: サイクルの長さ（128・160・192bar）と、イントロとブレイクダウンの長さ、イントロの入り順をサイクルごとに乱数で変え、ドロップが来るタイミングと長さ、イントロの始まり方を毎回同じにしない

エネルギーの段階は、低（ブレイクダウン）・中（イントロ）・上昇（ビルド）・高（ドロップ）の4つです。サイクルは 174 BPM で約3〜4.5分なので、1時間で約16回巡り、この段階が数分おきに入れ替わります。

## 和声の考え方

- 旋法はナチュラルマイナーに固定し、コードの構成音を鳴らす限り調性が崩れないようにする
- テンションと借用和音で色合いを足すが、テンションは上モノだけが鳴らし、ベースはコードの構成音を保つ。低域の土台を濁らせないため
- 音階の外に出るのは借用和音の構成音だけにし、聴き手が「外れた」と感じる音を、その瞬間に限る

## 生成と再生を分ける

何を鳴らすか（生成）と、いつ・どう鳴らすか（再生）を分けます。生成は音を出さず、2bar ごとのイベントの列を返すだけです。ブラウザの音声に依存しないので、同じ生成をシミュレーションと単体テストからそのまま呼べ、長時間の統計と性質を音なしで確かめられます。詳しくは [アーキテクチャ](./architecture.md) に書きます。

## 扱わないこと

| 扱わないこと | 理由 |
| --- | --- |
| サブジャンル別のプリセット、音声の書き出し、MIDI の出力、ユーザーのサンプル | 聴き続ける道具という目的の外にあるため |
| ナチュラルマイナー以外の旋法、平行調・同主調への転調 | 長調の旋法を導入しないと表せず、調性の土台が揺らぐため |
| 変異やフィルの履歴の表示、キー・コード・シーン名の表示 | 画面が音を聴く邪魔をしないようにするため |
| アレンジを切るスイッチ、シーンの手動の切り替え | 展開を任せて聴く道具にするため |
| 音色や表（進行・重み表・シーン構成）を画面や設定ファイルで編集すること | 型で守っている不変条件（表にない音色やアボイドノートを作れないこと）が崩れるため |
| 設定を画面から保存する機能とプリセット | 設定ファイルは読むだけにし、配布先ごとの初期値を変える手段に留めるため |
| ページ独自のキーボードショートカット | キーボードでの操作は、Tab での移動と、ボタン・スライダーの標準のキー操作で満たすため |
| メニューを閉じるボタン以外で閉じること | 値を調整しながら再生・停止の操作もできるようにするため |
| メディア操作の曲送り・曲戻し・シーク | 曲に終わりがなく、戻る位置もないため |
| OS の共有シート（Web Share API） | 共有はシードを含めた URL のコピーで足りるため |
| 日本語と英語以外の言語、言語を切り替える操作 | 日本語を読めない人には、英語のほうが読める人が多いため。ブラウザの言語をその人が読める言語の申告として扱い、初期画面とメニューに置くものを増やさないため |
