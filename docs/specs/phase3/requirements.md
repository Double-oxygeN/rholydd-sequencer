# フェーズ3要件定義書（FX とアレンジ）

## 目的とスコープ

フェーズ3の目的は、フェーズ2までの「32bar 単位でまとまりのある展開」の上に、2つの要素を加えることです。1つは、128〜192bar のサイクルでシーン（イントロ・ビルド・ドロップ・ブレイクダウン）を巡らせるアレンジ層です。もう1つは、シーンの切り替わりを演出する FX です。そのうえで、次の2点を検証します。

- 1時間聴き続けても展開の起伏を感じ、単調に聞こえる時間帯がない
- シーンの切り替わりが自然に聞こえ、特にドロップの入りが聴かせどころとして機能する

**フェーズ3に含むもの**

- 128〜192bar（32bar 単位）のサイクルと、サイクル内のシーンの並び（レイアウト）
- シーンごとのパートの出し入れとエネルギー
- 主題（主進行と、音程のあるパートの型・フレーズ）をサイクル内で共有し、ドロップのたびに再現する仕組み
- 2周目以降のサイクルでも自然に聞こえ、毎回新しい曲のように始まるイントロ
- サイクルの頭で、ときどき近親調（属調・下属調）に移調する仕組みと、キーのパラメーターの初期キーへの変更
- シーンの境界に合わせたフィル（ドロップ直前の溜めを含む）
- FX: ライザー、インパクト、リバーブスロー、フィルタースイープのオートメーション
- FX のミキサーチャンネル
- 上記に伴う位置表示・シミュレーションツールの拡張

**フェーズ3に含まないもの（後続フェーズ）**

- パターンや FX の可視化、変異やフィルの履歴の表示（フェーズ4）
- アレンジを切ってフェーズ2の鳴り方に戻すスイッチ、シーンの手動切り替え、シーンの長さや並びの UI
- FX の音色やシーンの表（パート構成・エネルギー）を変える UI。設定ファイルの定数として持つ
- ミキサー設定の保存とプリセット（フェーズ2から持ち越し）

## 聴かせどころと緩急の考え方

パターンが無限に生成され続けると、どの瞬間も同じくらい「それなり」に聞こえ、山も谷もない状態に陥りやすくなります。フェーズ3では、次の5つの原則で起伏を作ります。

1. **対比で山を作る**: ドロップの迫力は、ドロップ自体の密度よりも、直前のブレイクダウンやビルドとの落差で決まる。ブレイクダウンではキック・スネア・ベースを抜き、ハイハットと和声だけに絞る
2. **期待を溜めてから解放する**: ビルドでは低域を抜き、ライザーとハイパスで緊張を上げ続け、ドロップ直前の1拍を無音にする。ドロップの頭でインパクト・キック・サブベースを同時に戻し、溜めた期待を一気に解放する
3. **戻ってきた主題で聴かせる**: 2回目のドロップでは、1回目と同じ進行・ベースライン・スタブが戻ってくる。聴き覚えのあるものが戻る瞬間が、生成音楽で最も「聴かせどころ」として認識されやすいため。ドラムのグルーヴだけは強い変異で変え、同じものの繰り返しには聞こえないようにする
4. **サイクルを1曲として区切る**: サイクルの中では主題を共有して統一感を持たせ、サイクルの頭で主題とグルーヴを入れ替える。ときにはキーも近親調に移し、続くサイクルの響きの色合いを変える。イントロはサイクルごとに戻し、薄いドラムとパッドだけの8bar から始め直す。ドラムは途切れさせず、DJ ミックスで次の曲のイントロにつなぐように聞かせる
5. **周期をずらす**: サイクルの長さ（128・160・192bar）、イントロとブレイクダウンの長さをサイクルごとに乱数で変え、ドロップが来るタイミングとドロップの長さを毎回同じにしない

エネルギーの段階は、低（ブレイクダウン）・中（イントロ）・上昇（ビルド）・高（ドロップ）の4つです。サイクルは174 BPM で約3〜4.5分なので、1時間で約16回巡り、この段階が数分おきに入れ替わります。

## フェーズ2要件からの変更点

MVP、フェーズ1、フェーズ2の要件は、ここに挙げたもの以外すべて引き継ぎます。

| 対象 | フェーズ2 | フェーズ3 |
| --- | --- | --- |
| パートの出し入れ | ミュートしたパートを除き、全パートが常に鳴る | シーンごとに鳴らすパートを決める（F-57）。ユーザーのミュートはこれまでどおり再生側で扱う |
| F-21 エネルギーカーブ | 32bar 内の位置だけで決まる（A 0.75, A' 0.9, B 0.5, A'' 1.0） | シーンと、シーン内の位置で決まる。ドロップはフェーズ1のカーブをそのまま使う（F-54） |
| F-18 強い変異 | 32bar 境界ごとに `m32` で基準パターンを変異させる | サイクルの頭と、サイクルの最初のドロップの頭を除くドロップの各32bar の頭でだけ変異させる（F-56）。それ以外の32bar 境界では基準を引き継ぐ |
| F-34 主進行の交替 | 32bar 境界ごとに確率 `m32` で替わる | サイクルの頭でだけ確率 `m32` で替わる（F-55）。転換進行は従来どおり32bar ごとに選ぶ |
| 音程のあるパートの型とフレーズ | A・A'・A'' 用の型と乱数列を32bar ごとに選ぶ | サイクルごとに選び、サイクル内の全32bar で共有する（F-55）。B 用は従来どおり32bar ごと |
| 大きなフィル（32bar の終わり） | 種類を5つから均等に選ぶ | 次のシーンがドロップのときはロール系の3つに限り、最後の1拍を全パート無音にする（F-59） |
| 8bar の終わりのフィル | 確率 `fillIntensity` で入る | シーンが変わる8bar の終わりでは、`fillIntensity` が0でない限り必ず入る（F-58） |
| F-26・F-30 キー | 停止中にだけ選べ、再生中は固定。音程のある全パートの移調だけに効く | 初期キーに改める。初期キーは最初のサイクルのキーで、2つ目以降のサイクルのキーは初期キーからの移調の幅で決まる（F-70）。移調の幅は乱数だけで決まり、初期キーによらない。初期キーは引き続き停止中にだけ選べ、どのシードにも混ぜない |
| F-23・F-32 音階 | ベースとコードの音はキーのナチュラルマイナーの音 | そのサイクルのキーのナチュラルマイナーの音 |
| F-47 停止 | 全パート・リバーブの残響・予約済みのダッキングが止まる | FX、FX の残響、予約済みのオートメーション（フィルタースイープ、リバーブスロー）も止まり、フィルターは開いた状態に戻る（F-66） |
| `Context` | 構造、パラメーター、8bar の進行、セッション固定のキー | サイクル内の位置とシーンを加え、キーをサイクルごとのキーにする |
| 生成の出力 | ドラムと音程のある4パートのイベント | FX のイベントを加える |
| ミキサー | 9チャンネル | FX のチャンネルを加える（F-65） |

同じシードでも、フェーズ2と同じ曲にはなりません。主題の共有と強い変異のタイミングが変わり、サイクルごとに移調するためです。

## システム構成

生成と再生の分離は変えません。生成側は2bar ごとに次の順で進みます。

1. コンダクターが、サイクル内の位置とシーン、サイクルのキー、32bar 内の位置、エネルギー、8bar の進行を含む構造のコンテキストを作る
2. ドラム生成器が、構造のコンテキストからドラムの確定結果を作る
3. 構造のコンテキストにドラムの確定結果を加えたコンテキストを作る
4. 音程のある4パートの各生成器が、そのコンテキストからノートを作る
5. アレンジが、シーンで鳴らさないパートのイベントを取り除く
6. FX 生成器が、構造のコンテキストと手順5で残ったイベントから FX のイベントを作る（リバーブスローは、実際に鳴る最後のスネアに合わせるため）

手順2〜4は、シーンにかかわらず全パートぶん実行します。鳴らさないパートも生成を続けることで、乱数列がシーンの並びに左右されず、パートが戻ってきたときにその時点の続きから鳴るようにするためです。パートの出し入れを再生側のミュートで扱わないのは、シミュレーションと単体テストで「ブレイクダウンにキックがない」ことを検証できるようにするためです。

ダッキングのトリガーには、手順5の後に残ったキックを使います。キックを抜いたシーンではダッキングしません。

再生側の信号の流れは次のとおりです。フェーズ2から次の4つが変わります。

- FX のチャンネルを加える
- リバーブスロー用のセンドを加える
- 音程のあるパートに、イントロ用のローパスを加える
- マスターのコンプレッサーの前に、ビルド用のハイパスを加える

```
ドラム4パート ─▶ [ch] ─▶ ドラムバス（Comp）───────────┐
sub, reese, pad ─▶ [LPF] ─▶ [ダッキング] ─▶ [ch] ───────┤
stab ─────────────▶ [LPF] ─────────────────▶ [ch] ───────┤
FX（ライザー、インパクト）──────────────────▶ [ch] ───────┼─▶ HPF ─▶ マスター（Comp ─▶ Limiter）─▶ クリップ検出 ─▶ 音量 ─▶ 出力
  [ch] のセンド ───────────────────────▶ リバーブ ─▶ [リターン] ┤
  snare のスロー用センド ───────────────▶ リバーブ              │
```

`[LPF]` は音程のある4パートで共通に動かすイントロ用のローパスです。チャンネルより前に置くので、リバーブへの送りにもかかります。

FX のオートメーションは、ユーザーのミキサー設定を書き換えません。リバーブスローは通常のセンドとは別の経路で送り、フィルタースイープはミキサーの外にあるフィルターを動かします。ミキサーの操作とオートメーションが同じ値を取り合わないようにするためです（N-11 の維持）。

## 生成ロジック仕様

### サイクルとシーン

サイクルは32bar を4〜6つ並べたもので、次の4つの部分からなります。32bar の中の A A' B A''（フェーズ1）は、どのシーンでもそのまま保ちます。

| 部分 | 長さ | 8bar の割り当て（A, A', B, A''） |
| --- | --- | --- |
| イントロ＋ビルド | 32bar | レイアウトにより「イントロ, イントロ, イントロ, ビルド」か「イントロ, イントロ, ビルド, ビルド」 |
| ドロップ1 | 32bar か 64bar | すべてドロップ |
| ブレイクダウン＋ビルド | 32bar | レイアウトにより「ブレイクダウン, ブレイクダウン, ブレイクダウン, ビルド」か「ブレイクダウン, ブレイクダウン, ビルド, ビルド」 |
| ドロップ2 | 32bar か 64bar | すべてドロップ |

**レイアウト**: サイクルの頭で乱数を3回引き、次の3つを決めます。

| 項目 | 選択肢と確率 |
| --- | --- |
| イントロの長さ | 24bar か 16bar を 0.5 ずつ。ビルドはその残り（8bar か 16bar） |
| ブレイクダウンの長さ | 24bar か 16bar を 0.5 ずつ。ビルドはその残り（8bar か 16bar） |
| ドロップの延長 | なし（128bar）1/3、ドロップ1だけ（160bar）1/6、ドロップ2だけ（160bar）1/6、両方（192bar）1/3 |

サイクルの長さが128・160・192bar になる確率は、それぞれ 1/3 です。

ドロップを常に32bar 境界から始めるのは、フェーズ1で確立した「32bar の区切りを聴き取れる」構造の上で、最も強い区切りに最も大きな変化を重ねるためです。ビルドを32bar の終わりに置くと、32bar の終わりの大きなフィルがそのままドロップへの導入になります。

**可変長の部分をドロップの延長に充てる理由**: ドロップは聴かせどころなので、長く浸りたいときと短く切り替えたいときの両方があります。延長したドロップは、2つ目の32bar の頭でドラムのグルーヴだけを変え（F-56）、主題はそのまま続けます。ブレイクダウンを増やす案も考えましたが、サイクル内でドロップが3回になると、主題の再現が「聴かせどころ」から「繰り返し」に変わってしまうため採りません。

### イントロ

イントロは、サイクルの頭で新しい主題と新しいグルーヴを提示するシーンです。再生開始時も2周目以降も同じ形で始め、毎回新しい曲が始まったように聞かせます。

| 区間 | ドラム | サブベース | パッド |
| --- | --- | --- | --- |
| 最初の8bar | キック、スネア、8分の位置のハイハットだけ。ゴーストと16分の裏のハイハットを抜く | 鳴らさない | 鳴らす（ローパスが開いていく） |
| 2つ目以降の8bar | すべて | 鳴らす | 鳴らす |

- **最初の8bar を薄くする理由**: エネルギーによる間引きでは、弱い位置の打音しか抜けず、音数はほとんど減りません（シミュレーションでは、エネルギーを下げたイントロの最初の8bar もドロップも、1小節あたり約13打でした）。そこで、パートと位置ごと抜きます。ゴーストと16分の裏のハイハットを抜くと、1小節あたり約8打になります
- **2周目以降も同じ形にする理由**: ドロップ2の大きなフィルの後でいったん薄いビートに戻すと、次の曲に移ったことがはっきり伝わります。ドラム自体は途切れさせないので、曲が止まったようには聞こえません
- **ドラムにローパスをかけない理由**: ドロップから移った直後にドラムまでこもると、曲が止まったように聞こえるためです。ローパスは音程のあるパートだけにかけ、新しい主題の和声がこもった状態から開いていくようにします
- サイクルの頭ではドラムの基準パターンに強い変異をかけるので（F-56）、グルーヴの変化も「次の曲に移った」合図になります

### シーンごとのパート

○は鳴らし、×は鳴らさないパートです。

| パート | イントロ | ビルド | ドロップ | ブレイクダウン |
| --- | --- | --- | --- | --- |
| キック | ○ | ○ | ○ | × |
| スネア | ○ | ○ | ○ | ×（最後のフィルだけ鳴らす。F-58） |
| ハイハット | ○（最初の8bar は8分の位置だけ） | ○ | ○ | ○ |
| ゴースト | ○（最初の8bar は ×） | ○ | ○ | × |
| サブベース | ○（最初の8bar は ×） | × | ○ | × |
| リースベース | × | × | ○ | × |
| スタブ | × | ○ | ○ | ○ |
| パッド | ○ | ○ | ○ | ○ |

- リースベースはドロップだけに置き、ドロップの「顔」にします。リースベースが聞こえたらドロップだと分かるようにするためです
- ビルドではサブベースとリースベースを抜き、低域を空けます。ドロップの頭でサブベースが戻ったときの落差が最大になるようにするためです
- ブレイクダウンでは、ハイハットとスタブ・パッドで進行を聴かせます。ドロップと同じ主進行を和声だけで聴かせておくと、ドロップ2で主題が戻ったと感じやすくなります

### エネルギー

エネルギーは8bar の頭で、シーンとシーン内の位置から次の式で決めます。8bar の間は変えません（フェーズ1のまま）。

```
E = 1 − energyDepth × (1 − カーブの値)
```

| シーン | カーブの値 |
| --- | --- |
| イントロ | 0.5（全8bar） |
| ビルド | 8bar のとき 0.75。16bar のとき 1つ目 0.6、2つ目 0.75 |
| ドロップ | 32bar ごとにフェーズ1のカーブ（A 0.75, A' 0.9, B 0.5, A'' 1.0） |
| ブレイクダウン | 0.4（全8bar） |

- **ビルド**: 単調増加にし、フェーズ1のカーブ（B で 0.5 に落ちる）を掛けません。上昇の途中で谷を作らないためです
- **ビルドの上限**: ドロップの A（0.75）に揃えます。ドロップの頭でドラムがビルドより薄くならないようにするためです。ビルドの緊張の高まりは、エネルギーよりもライザーとハイパスのスイープで作ります
- **ドロップ**: フェーズ1のカーブを使います。ドロップの32bar の中に A A' B A'' の起伏を残し、32bar の区切りを聴き取れるようにするためです

### 主題の共有

サイクル内の32bar は、1つの曲の中の各部分として、同じ主題を共有します。

| 要素 | 決めるタイミング | 共有する範囲 |
| --- | --- | --- |
| 主進行 | サイクルの頭。前のサイクルから確率 `m32` で替わる（フェーズ2の主進行の選択を、32bar ごとからサイクルごとに移す） | サイクル内の A・A'・A'' |
| 転換進行 | 32bar の頭（フェーズ2のまま） | その32bar の B |
| 音程のあるパートの A・A'・A'' 用の型と乱数列 | サイクルの頭 | サイクル内の A・A'・A'' |
| 音程のあるパートの B 用の型と乱数列 | 32bar の頭（フェーズ2のまま） | その32bar の B |
| ドラムの基準パターン | サイクルの頭と、ドロップの32bar の頭（サイクルの最初のドロップの頭を除く）で、`m32` に従って強い変異をかける | 次に変異するまで |

**ドロップの間で戻るもの**: サイクル内のすべてのドロップの32bar で、A・A'・A'' の進行・リースベース・スタブ・パッドが同じ形で戻ります。ドラムのグルーヴは32bar ごとに変わります。

**ドロップごとに変わるもの**

- B は32bar ごとに選び直す転換進行と型で鳴る
- 32bar の終わりの大きなフィルの長さ（16か32ステップ）は32bar ごとに選ぶ。そのため A'' の最後の2bar では、音程のあるパートの打ち切り位置が変わることがある
- サブベースはキックに従うので、新しいグルーヴに合わせてリズムが変わる

**サイクル全体のまとまり**: イントロとブレイクダウンにも同じ主題が（パートを抜いた形で）流れるので、サイクル全体が1曲としてまとまって聞こえます。

`m32` が 0 のときは、主進行も基準パターンもキーも最初のまま変わりません（フェーズ2と同じ意味）。音程のあるパートの型とフレーズは、サイクルごとに選び直します。

### 移調

主題とグルーヴを入れ替えても、キーがずっと同じだと、どのサイクルも同じ響きの上で鳴り、続けて聴くと区別がつきにくくなります。そこで、サイクルの頭でときどき近親調に移調します。

**移調先**: 旋法はナチュラルマイナーに固定しているので、近親調のうち同じ旋法で表せる属調（主音が完全5度上）と下属調（完全4度上）だけを使います。どちらも元のキーと音階の6音を共有するので、移っても響きが急に変わりすぎません。DJ がキーの合う曲をつなぐときに、五度圏で隣のキーを選ぶ（ハーモニックミックス）のと同じ関係です。平行調と同主調は、長調の旋法を導入しないと表せないため扱いません。

| 前のサイクルのキー | 移調するとき | 移調しないとき |
| --- | --- | --- |
| 初期キー | 属調か下属調を 0.5 ずつ | 初期キーのまま |
| 属調 | 初期キー | 属調のまま |
| 下属調 | 初期キー | 下属調のまま |

- **移調の確率**: 2つ目以降のサイクルの頭で `m32 / 2`。既定値の `m32 = 0.6` で 0.3 なので、1時間（約16サイクル）で4〜5回移調する。主進行の交替と同じく `m32` に従わせ、`m32` の1つでサイクルごとの変化の大きさを決められるようにする。主進行より確率を下げるのは、移調は主進行の交替より目立つ変化で、続けて起きると落ち着かないため
- **キーを初期キーの両隣に留める理由**: 属調から属調へと同じ向きに移り続けると、1時間のうちに五度圏を巡って初期キーとの関係が失われ、選んだ初期キーの意味がなくなる。両隣に留めれば、初期キーを「ホーム」として、離れては戻る形になる
- **移調をサイクルの頭に置く理由**: イントロの最初の8bar はローパスを閉じたパッドと薄いドラムだけで始まるので、新しいキーの和声がこもった状態から現れ、唐突に聞こえない。主題とグルーヴも同時に入れ替わるので、「次の曲に移った」合図がより強くなる
- 移調は、主進行の交替とは独立に決める。主進行が同じまま移調することも、移調せずに主進行だけ替わることもある
- 各パートは、どのキーでも決められた音域に折り返す（フェーズ1・2のまま）ので、移調しても音域は変わらない

### シーンの境界のフィル

| 境界 | フィル |
| --- | --- |
| イントロ → ビルド（8bar 境界） | 8bar の終わりのフィルを必ず入れる。種類と長さはフェーズ1のまま |
| ビルド → ドロップ（32bar 境界） | 大きなフィルを、スネアロール・加速ロール・後半ロールから選ぶ。長さは従来どおり16か32ステップ。最後の1拍（ステップ 28〜31）は溜めとし、ドラムのフィルも含めて全パートを鳴らさない。パッドも溜めの頭で止める（後述） |
| ドロップ → ドロップ（延長。32bar 境界） | 大きなフィル（フェーズ2のまま） |
| ドロップ1 → ブレイクダウン（32bar 境界） | 大きなフィル（フェーズ2のまま） |
| ブレイクダウン → ビルド（8bar 境界） | 8bar の終わりのフィルを必ず入れ、種類はスネアロールとする。長さは従来どおり選ぶ。ブレイクダウンで抜いているドラムのうち、このフィルのスネアだけは鳴らし、ドラムが戻ってくることを予告する |
| ドロップ2 → 次のサイクルのイントロ（32bar 境界） | 大きなフィル（フェーズ2のまま） |

**溜めの中の音**: 溜めの中で鳴ってよいのは、リバーブの残響（リバーブスローを含む）とライザーの消え際だけです。パッドのノートは溜めの頭で終わるように長さを決めます。ただし、パッドのリリース（約 1.2 秒）は174 BPM の1拍（約 0.34 秒）より長く、そのままでは溜めを埋めてしまいます。そのため再生側で、溜めの頭でパッドを短いフェードで切ります。

フィルの種類を選ぶ乱数の引き方は変えず、選ぶ表だけをシーンの境界に応じて差し替えます。ドロップの前をロール系に限るのは、ドロップアウトやゴーストラッシュでは、溜めの前に緊張が上がりきらないためです。

### FX

すべての FX は、生成側で2bar ごとのイベントとして決めます。2bar をまたぐ FX は、その2bar 内の区間に分けて出します。区間は、開始ステップ、終了ステップ、開始時と終了時の進み具合で表します。進み具合はシーン内の位置だけから決まるので、どの2bar から見ても同じ値になり、乱数は使いません。

**ライザー**: ビルドの頭から溜めの直前（ドロップの1拍前）までを進み具合 0 → 1 とし、ホワイトノイズのバンドパスの中心周波数と音量を上げていきます。溜めの頭で鳴り止みます。音が止まった後に残る無音と、リバーブスローの残響が溜めになります。

**インパクト**: ビルドの後のドロップの頭（ステップ0）で1回鳴らします。延長したドロップの2つ目の32bar の頭は、大きな区切りではあってもシーンの切り替わりではないので鳴らしません。インパクトは、ピッチが下がるサイン波とノイズのバーストを重ねた合成音です。キック・サブベースと同じ瞬間に低域が重なるため、インパクトの低域はサブベースの帯域より上で鳴らすか十分に下げ、N-10（クリップしない）を満たすようにします。具体的な音色は設計書で決めます。

**リバーブスロー**: 次の2か所の直前の2bar で、最後に鳴るスネアの打音1つを、通常のセンドとは別の経路でリバーブに大きく送ります。

- ビルドの後のドロップの直前: 溜めの直前のスネア
- ドロップ1の後のブレイクダウンの直前: 32bar の最後のスネア

スネアが鳴らない（大きなフィルがドロップアウトなど）ときはスローしません。

**フィルタースイープ**: 音程のある4パートに共通のローパスを1つ、マスターのコンプレッサーの前にハイパスを1つ置きます。

| シーン | 動き |
| --- | --- |
| イントロ | 音程のあるパートのローパスを、閉じた状態からイントロの最後の8bar の頭までに開ききる |
| ビルド | ミックス全体のハイパスを、開いた状態（可聴域の下端）から溜めの頭まで上げ続ける |
| ビルドの後のドロップの頭 | ハイパスとローパスを開いた状態に戻す |
| それ以外 | 開いたまま動かさない |

周波数の範囲とカーブは設計書で決めます。周波数は対数的に動かし、耳で聞いて一定の速さで変わるようにします。

### データ構造

```ts
type CycleIndex = Brand<number, 'CycleIndex'>;   // 再生開始からのサイクルの数

// 前半（イントロかブレイクダウン）の8bar の数。ビルドは同じ32bar の残り（4 − 前半）から決まり、別に持たない
type LeadSections = 2 | 3;
type DropPhrases = 1 | 2;

// サイクルのレイアウト。サイクルの長さは 32bar × (2 + firstDrop + secondDrop) から決まり、別に持たない
interface CycleLayout {
  readonly intro: LeadSections;
  readonly breakdown: LeadSections;
  readonly firstDrop: DropPhrases;
  readonly secondDrop: DropPhrases;
}

// シーン内の位置。長さと位置を組にし、長さを超える位置を表現できないようにする
type LeadPosition  = { sections: 2; index: 0 | 1 } | { sections: 3; index: 0 | 1 | 2 };
type BuildPosition = { sections: 1; index: 0 } | { sections: 2; index: 0 | 1 };
type DropPosition  = { phrases: 1; phrase: 0 } | { phrases: 2; phrase: 0 | 1 };

// シーンは判別共用体にし、シーンごとに意味のある情報だけを持たせる
type SceneRole =
  | ({ scene: 'intro' } & LeadPosition)
  | ({ scene: 'build' } & BuildPosition)                             // 直後は必ずドロップ
  | ({ scene: 'drop'; drop: 'first' | 'second' } & DropPosition)
  | ({ scene: 'breakdown' } & LeadPosition);

type SectionInCycle = Brand<number, 'SectionInCycle'>;   // サイクル内の8bar の番号

// 初期キーから五度圏で何歩離れているか。下属調 −1、初期キー 0、属調 1 の3つしか表現できない
type FifthsFromInitial = -1 | 0 | 1;

// Context に追加するもの。コンダクターが作る
interface ArrangementContext {
  readonly cycle: CycleIndex;
  readonly layout: CycleLayout;
  readonly sectionInCycle: SectionInCycle;
  readonly sceneRole: SceneRole;
  // Context は2bar ごとに独立して作るので、次の8bar のシーンを持たせる。サイクルの最後では次のサイクルのイントロ
  readonly nextScene: SceneRole['scene'];
  // そのサイクルのキー（初期キーを FifthsFromInitial だけ移調したもの）。フェーズ2までのセッション固定のキーを置き換える
  readonly key: Key;
}
// Seeds には、サイクル内で共有するシード cycle を加える

type StepEnd = Brand<number, 'StepEnd'>;   // 区間の終わり（その位置は含まない）。1〜32

// 2bar 内の区間。progress はシーン内の進み具合（0〜1）
interface FxSpan { from: Step; to: StepEnd; startProgress: UnitInterval; endProgress: UnitInterval }

interface RiserSegment { fx: 'riser'; span: FxSpan }
interface Impact       { fx: 'impact'; step: Step }
interface ReverbThrow  { fx: 'throw'; step: Step }                       // 対象はスネアだけ
interface SweepSegment { fx: 'sweep'; filter: 'lowpass' | 'highpass'; span: FxSpan }
interface FilterReset  { fx: 'filterReset'; step: Step }                 // ビルドの後のドロップの頭
interface Gap          { fx: 'gap'; from: Step }                         // 溜め。その2bar の終わりまで。再生側はパッドを切る
type FxEvent = RiserSegment | Impact | ReverbThrow | SweepSegment | FilterReset | Gap;
```

`SceneRole` と、`Context` がすでに持つ8bar の役割（`sectionRole`）との対応は、サイクル内の位置とレイアウトから一意に決まります。食い違う組を作れないよう、コンダクターだけが両方を作ります。サイクルの長さが一定でないので、小節の通し番号からサイクルの番号を計算では求められません。コンダクターがサイクルの頭と長さを保持して進めます。

コンダクターは、キーそのものではなく `FifthsFromInitial` をサイクルごとに保持し、そこから `Context` のキーを求めます。キーそのものを積み重ねて持つと、初期キーの両隣に留まっているかを型で保証できないためです。

ミキサーの設定に、FX のチャンネル `fx: SendingChannel` を加えます。

### シードの派生

フェーズ2までの派生はすべて引き継ぎ、次を加えます（タグの値は19から）。初期キーとミキサーの設定はどのシードにも混ぜません。32bar のシード（`phrase`）は、これまでどおり再生開始からの32bar の通し番号から派生します。

- サイクル: `cycle = hash(master, TAG.cycle, サイクルの番号)`
- レイアウト: `hash(cycle, TAG.layout)`。イントロの長さ、ブレイクダウンの長さ、ドロップの延長の順に引く
- 主進行: `hash(cycle, TAG.progression)`。変化の判定、主進行の順に引く
- 移調: `hash(cycle, TAG.modulation)`。移調の判定、移調先（属調か下属調か）の順に、どのキーにいても2つとも引く。移調先は初期キーにいるときだけ使う。最初のサイクルでは引かない
- 転換進行: フェーズ2のまま `hash(phrase, TAG.progression)` から引く。主進行の選択に使っていた2つの値は、引いたうえで使わない（乱数の引き方を変えないため）
- 音程のあるパートの型: A・A'・A'' 用は `hash(cycle, TAG.xxxStyle)` から型の表全体で選ぶ。B 用は `hash(phrase, TAG.xxxStyle)` から、そのサイクルの A 用の型を除いた残りで選ぶ（F-38 を保つため）
- 音程のあるパートの A・A'・A'' のフレーズ: `hash(cycle, TAG.xxxRhythm / xxxPitch, REL[pairRelation])`。B はフェーズ2のまま `section` から派生する
- ドラムの強い変異: フェーズ1のまま `hash(phrase, TAG.mutate32, パート番号)`。変異を行う32bar だけで使う
- FX は乱数を使わない

## パラメーター仕様

新しい生成パラメーターは加えません。既存のパラメーターは、次の点だけ意味が変わります。

| 名前 | キー | フェーズ3での効き方 |
| --- | --- | --- |
| 初期キー | `initialKey` | フェーズ2までの「キー」（`key`）を改めたもの。最初のサイクルのキーで、移調はここを起点とし、ここに戻る（F-70）。範囲・既定値（F）・停止中にだけ変えられることはフェーズ2のまま |
| 32bar 変化率 | `m32` | サイクルの頭で主進行が替わる確率。その半分が、サイクルの頭で移調する確率。サイクルの頭とドロップの32bar の頭での強い変異の量 |
| エネルギーの起伏 | `energyDepth` | シーンのカーブにかける深さ。0 のとき全シーンでエネルギーが1になる（パートの出し入れと FX は残る） |
| フィル強度 | `fillIntensity` | 0 のとき、シーンの境界の必須フィルも、大きなフィルも入らない。溜めとリバーブスローは残る |

**ミキサー**に FX のチャンネルを加えます。範囲と表示は他のチャンネルと同じです。既定値は設計書で決め、試聴で確定します。

次のものは UI に出さず、設定ファイルの定数として持ちます。

- シーンの表（パート構成・エネルギー）
- レイアウトの確率
- 移調の確率の `m32` に対する割合（1/2）
- FX の音色とスイープの範囲
- リバーブスローの送り量

## 非機能要件

MVP からフェーズ2までの N-01〜N-11 を、FX とオートメーションを含めて引き継ぎます。N-03 の「2bar 分の生成処理が 5ms 以内」は、アレンジと FX の生成を含めた合計で満たします。

| ID | 区分 | 要件 |
| --- | --- | --- |
| N-12 | 性能 | 全パートと FX、スイープ用のフィルターを既定のミキサー設定で鳴らしても、MVP と同じ環境で処理落ちによる音切れが起きないこと |
| N-13 | 音質 | ドロップの頭（インパクト・キック・サブベースが重なる瞬間）を含め、既定の設定でリミッターの後の出力が 0 dBFS を超えないこと |
| N-14 | 再現性 | 同じシードとパラメーターなら、シーンの並び、FX のイベント、オートメーションの値が一致すること。ミキサーの操作でこれらが変わらないこと |

## 受け入れ基準

自動テストと試聴、長時間動作の3つを満たした時点でフェーズ3完了とします。

**自動テスト**

- [x] MVP からフェーズ2までの自動テストの受け入れ基準を、変更点の表で改めたものも含めて、フェーズ3の生成器ですべて満たす
- [x] すべてのサイクルで、長さが128・160・192bar のいずれかで、シーンの並びが F-52・F-53 に従う。ドロップが32bar 境界で始まり、ビルドの直後が必ずドロップになる
- [x] 8192bar のシミュレーションで、イントロとブレイクダウンの長さの4通りと、ドロップの延長の4通り（なし、ドロップ1、ドロップ2、両方）がそれぞれ現れる
- [x] 各シーンで鳴らさないパートのイベントが1つもない（ブレイクダウンの最後のフィルのスネアを除く）
- [x] すべてのイントロの最初の8bar に、サブベースとゴーストと16分の裏のハイハットがなく、2つ目以降の8bar にはサブベースがある
- [x] ビルドのエネルギーが単調に増えてドロップの A を超えない。ドロップのエネルギーが32bar ごとにフェーズ1のカーブに従う。イントロのエネルギーが一定である。`energyDepth = 0` のとき全シーンでエネルギーが1になる
- [x] 主進行がサイクルの頭以外で変わらず、`m32 = 0` では最初の主進行のまま変わらない
- [ ] キーがサイクルの頭以外で変わらず、最初のサイクルは初期キーで、どのサイクルも初期キー・その属調・その下属調のいずれかである。変わるときは初期キーと属調・下属調の間だけを移り、属調と下属調の間を直接移らない。`m32 = 0` では初期キーのまま変わらない
- [ ] 8192bar のシミュレーションで、属調と下属調の両方が現れる
- [ ] 音程のある全パートの音が、そのサイクルのキーのナチュラルマイナーの音である
- [ ] 同じシードで初期キーだけを変えたとき、すべてのサイクルで初期キーからの移調の幅が一致し、音程のある全パートが初期キーの差だけ移調した音高になる
- [x] 同じサイクルのすべてのドロップの32bar の A・A'・A'' で、進行が一致し、大きなフィル区間より前のリースベース・スタブ・パッドのイベント列が一致する
- [x] 転換の8bar の音程のあるパートの型が、そのサイクルの A の型と異なる
- [x] ドラムの基準パターンが変わるのが、サイクルの頭と、サイクルの最初のドロップの頭を除くドロップの32bar の頭だけである
- [x] ドロップ直前の大きなフィルがロール系で、ステップ 28〜31 で鳴っている音がない（全イベントで `step + length ≤ 28`。ドラムは発音位置が 28 未満）
- [x] シーンが変わる8bar の終わりで、`fillIntensity > 0` なら必ずフィルが入る
- [x] インパクトが、ビルドの後のドロップの頭のステップ0にだけある
- [x] ライザーの区間がビルドの中にだけあり、途切れずにつながり、進み具合が単調に増えて溜めの頭で終わる
- [x] スイープのローパスはイントロにだけ、ハイパスはビルドにだけあり、ビルドの後のドロップの頭でリセットされる
- [x] リバーブスローが、ビルドの後のドロップと、ドロップ1の後のブレイクダウンの直前の2bar にだけあり、その2bar で最後に鳴るスネアの位置にある
- [x] 同じシードで2回生成したとき、ノートと FX のイベントが一致する
- [x] 2bar 生成処理（アレンジと FX を含む合計）の平均が 5ms 以内

**試聴（1時間）**

低域の評価はヘッドホンかモニタースピーカーで行います。

- [ ] 1時間の中で、展開の起伏を感じる。単調に感じて聞き流してしまう時間帯がない
- [ ] シーンの切り替わりが、唐突ではなく自然に聞こえる
- [ ] ドロップ2から次のサイクルのイントロに移るとき、曲が止まったようには聞こえず、次の曲に移ったと感じる
- [ ] ビルドで緊張が高まり、溜めからドロップの頭で解放される感覚がある
- [ ] ドロップ2で、ドロップ1の主題が戻ってきたと分かり、かつグルーヴの変化で新鮮さがある
- [ ] サイクルの頭の移調が唐突に聞こえず、移調したサイクルで響きの色合いが変わったと感じる
- [ ] 64bar のドロップが間延びしない
- [ ] ブレイクダウンが間延びせず、ドラムが戻る予告（スネアロール）が効いている
- [ ] FX が他のパートを覆い隠さず、ドロップの頭を含めてクリップの表示が一度も点かない
- [ ] 2bar ごとのコードの変化とシーンの起伏があっても、32bar の区切りを指摘できる
- [ ] 停止と再生を繰り返しても、前の再生の FX やフィルターの状態が残らない

**長時間動作**

- [ ] FX とオートメーションを含めた1時間連続再生で、メモリ使用量が安定している

## 確定した事項

要件のレビューを経て、次のとおり確定しました。

- サイクルは128bar 固定ではなく、128〜192bar の間で32bar 単位で変える。可変長の部分はドロップの延長に充てる
- イントロはサイクルごとに戻す。ローパスは音程のあるパートだけにかける
- イントロの最初の8bar は、再生開始時も2周目以降も、ゴーストと16分の裏のハイハットを抜いた薄いドラムとパッドで鳴らし、サブベースは2つ目の8bar から入れる（試聴を経て、2周目以降のエネルギーを段階的に下げる案から改めた）
- 主題はサイクル内で共有する。その代わり、同じシードでもフェーズ2と同じ曲にはならない

## 未決事項

試聴で決める点です。

- ビルドの終盤のドラムの密度。ビルドの上限をドロップの A に揃えたことで、物足りなくならないか
- シーンごとのエネルギーの値と、レイアウトの確率
- ライザーを溜めの頭で止めるか、ドロップの頭まで鳴らすか
- ドロップ2をドロップ1より盛り上げるための追加の変化（エネルギーカーブを上げる、スタブの型を選び直すなど）が必要か
- 移調の確率（`m32 / 2`）と、キーを初期キーの両隣に留める範囲（五度圏で2歩まで広げるか）
