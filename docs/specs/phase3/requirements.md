# フェーズ3要件定義書（FX とアレンジ）

## 目的とスコープ

フェーズ3の目的は、フェーズ2までの「32bar 単位でまとまりのある展開」の上に、128bar 単位でシーン（イントロ・ビルド・ドロップ・ブレイクダウン）を巡らせるアレンジ層と、シーンの切り替わりを演出する FX を加えることです。そのうえで、次の2点を検証します。

- 1時間聴き続けても展開の起伏を感じ、単調に聞こえる時間帯がない
- シーンの切り替わりが自然に聞こえ、特にドロップの入りが聴かせどころとして機能する

**フェーズ3に含むもの**

- 128bar のサイクルと、サイクル内のシーンの並び（レイアウト）
- シーンごとのパートの出し入れとエネルギー
- 主題（主進行と、音程のあるパートの型・フレーズ）を128bar で共有し、2回目のドロップで再現する仕組み
- シーンの境界に合わせたフィル（ドロップ直前の溜めを含む）
- FX: ライザー、インパクト、リバーブスロー、フィルタースイープのオートメーション
- FX のミキサーチャンネル
- 上記に伴う位置表示・シミュレーションツールの拡張

**フェーズ3に含まないもの（後続フェーズ）**

- パターンや FX の可視化、変異やフィルの履歴の表示（フェーズ4）
- アレンジを切ってフェーズ2の鳴り方に戻すスイッチ、シーンの手動切り替え、シーンの長さや並びの UI
- FX の音色やシーンの表（パート構成・エネルギー）を変える UI。設定ファイルの定数として持つ
- ミキサー設定の保存とプリセット（フェーズ2から持ち越し）

## 聴かせどころと緩急の考え方

パターンが無限に生成され続けると、どの瞬間も同じくらい「それなり」に聞こえ、山も谷もない状態に陥りやすくなります。フェーズ3では、次の4つの原則で起伏を作ります。

1. **対比で山を作る**: ドロップの迫力は、ドロップ自体の密度よりも、直前のブレイクダウンやビルドとの落差で決まる。ブレイクダウンではキック・スネア・ベースを抜き、ハイハットと和声だけに絞る
2. **期待を溜めてから解放する**: ビルドでは低域を抜き、ライザーとハイパスで緊張を上げ続け、ドロップ直前の1拍を無音にする。ドロップの頭でインパクト・キック・サブベースを同時に戻し、溜めた期待を一気に解放する
3. **戻ってきた主題で聴かせる**: 2回目のドロップでは、1回目と同じ進行・ベースライン・スタブが戻ってくる。聴き覚えのあるものが戻る瞬間が、生成音楽で最も「聴かせどころ」として認識されやすいため。ドラムのグルーヴだけは強い変異で変え、同じものの繰り返しには聞こえないようにする
4. **周期を少しずらす**: 128bar ごとにイントロやブレイクダウンの長さを乱数で変え、ドロップが来るタイミングを毎回同じにしない。音程のあるパートの型とフレーズは128bar ごとに選び直し、主進行は128bar ごとに `m32` の確率で入れ替わる

エネルギーの段階は、低（ブレイクダウン）・中（イントロ）・上昇（ビルド）・高（ドロップ）の4つです。1時間（約20サイクル）の中で、この段階が数分おきに入れ替わります。

同じシードでも、フェーズ2と同じ曲にはなりません。主題の共有と強い変異のタイミングが変わるためです。

## システム構成

生成と再生の分離は変えません。生成側は2bar ごとに次の順で進みます。

1. コンダクターが、128bar 内の位置とシーン、32bar 内の位置、エネルギー、8bar の進行を含む構造のコンテキストを作る
2. ドラム生成器が、構造のコンテキストからドラムの確定結果を作る
3. 構造のコンテキストにドラムの確定結果を加えたコンテキストを作る
4. 音程のある4パートの各生成器が、そのコンテキストからノートを作る
5. アレンジが、シーンで鳴らさないパートのイベントを取り除く
6. FX 生成器が、構造のコンテキストから FX のイベントを作る

手順2〜4は、シーンにかかわらず全パートぶん実行します。鳴らさないパートも生成を続けることで、乱数列がシーンの並びに左右されず、パートが戻ってきたときにその時点の続きから鳴るようにするためです。パートの出し入れを再生側のミュートで扱わないのは、シミュレーションと単体テストで「ブレイクダウンにキックがない」ことを検証できるようにするためです。

ダッキングのトリガーには、手順5の後に残ったキックを使います。キックを抜いたシーンではダッキングしません。

再生側の信号の流れは次のとおりです。フェーズ2から変わるのは、FX のチャンネル、リバーブスロー用のセンド、マスターのコンプレッサーの前に置くスイープ用のフィルターです。

```
ドラム4パート ─▶ [ch] ─▶ ドラムバス（Comp）─┐
sub, reese, pad ─▶ [ダッキング] ─▶ [ch] ─────┤
stab ─────────────────────▶ [ch] ─────────────┤
FX（ライザー、インパクト）──▶ [ch] ─────────────┼─▶ スイープ（HPF ─▶ LPF）─▶ マスター（Comp ─▶ Limiter）─▶ クリップ検出 ─▶ 音量 ─▶ 出力
  [ch] のセンド ─────────────▶ リバーブ ─▶ [リターン] ┤
  snare のスロー用センド ─────▶ リバーブ             │
```

FX のオートメーションは、ユーザーのミキサー設定を書き換えません。リバーブスローは通常のセンドとは別の経路で送り、フィルタースイープはミキサーの外にあるフィルターを動かします。ミキサーの操作とオートメーションが同じ値を取り合わないようにするためです（N-11 の維持）。

## 生成ロジック仕様

### サイクルとシーン

128bar のサイクルは32bar を4つ並べたもので、サイクル内の32bar の位置（`phraseIn128` = 0〜3）でシーンが決まります。32bar の中の A A' B A''（フェーズ1）はどのシーンでもそのまま保ちます。

| `phraseIn128` | シーン | 8bar の割り当て（A, A', B, A''） |
| --- | --- | --- |
| 0 | イントロ＋ビルド | レイアウトにより「イントロ, イントロ, イントロ, ビルド」か「イントロ, イントロ, ビルド, ビルド」 |
| 1 | ドロップ1 | ドロップ, ドロップ, ドロップ, ドロップ |
| 2 | ブレイクダウン＋ビルド | レイアウトにより「ブレイクダウン, ブレイクダウン, ブレイクダウン, ビルド」か「ブレイクダウン, ブレイクダウン, ビルド, ビルド」 |
| 3 | ドロップ2 | ドロップ, ドロップ, ドロップ, ドロップ |

**レイアウト**: サイクルの頭で乱数を2回引き、イントロの長さ（24bar か 16bar）とブレイクダウンの長さ（24bar か 16bar）をそれぞれ確率 0.5 で選びます。ビルドはその残り（8bar か 16bar）です。組み合わせは4通りで、ドロップが始まる位置は常に32bar 境界ですが、ドロップの前の溜めの長さ（ビルドの長さ）がサイクルごとに変わります。

ドロップを常に32bar 境界から始めるのは、フェーズ1で確立した「32bar の区切りを聴き取れる」構造の上で、最も強い区切りに最も大きな変化を重ねるためです。ビルドを32bar の終わりに置くと、32bar の終わりの大きなフィルがそのままドロップへの導入になります。

**ドロップ2の後のイントロ**: 次のサイクルのイントロは、ドラムを鳴らしたまま和声とリースベースを抜く「中くらいのエネルギー」のシーンです。DJ ミックスで次の曲のイントロにつなぐときの感覚に近く、ドロップ2の後に一度エネルギーを落とし、新しい主題を提示する役割を持ちます。再生開始時のイントロも同じシーンで、フィルタースイープで音が開いていくことで導入らしさを出します。

### シーンごとのパート

○は鳴らし、×は鳴らさないパートです。

| パート | イントロ | ビルド | ドロップ | ブレイクダウン |
| --- | --- | --- | --- | --- |
| キック | ○ | ○ | ○ | × |
| スネア | ○ | ○ | ○ | ×（最後のフィルだけ鳴らす。F-58） |
| ハイハット | ○ | ○ | ○ | ○ |
| ゴースト | ○ | ○ | ○ | × |
| サブベース | 2つ目の8bar から ○ | × | ○ | × |
| リースベース | × | × | ○ | × |
| スタブ | × | ○ | ○ | ○ |
| パッド | ○ | ○ | ○ | ○ |

- リースベースはドロップだけに置き、ドロップの「顔」にします。リースベースが聞こえたらドロップだと分かるようにするためです
- ビルドではサブベースとリースベースを抜き、低域を空けます。ドロップの頭でサブベースが戻ったときの落差が最大になるようにするためです
- ブレイクダウンでは、ハイハットとスタブ・パッドで進行を聴かせます。ドロップと同じ主進行を和声だけで聴かせておくと、ドロップ2で主題が戻ったと感じやすくなります
- イントロの最初の8bar はサブベースも抜き、ドラムとパッドだけにします

### エネルギー

エネルギーは8bar の頭で、シーンとシーン内の位置から次の式で決めます。8bar の間は変えません（フェーズ1のまま）。

```
E = 1 − energyDepth × (1 − カーブの値)
```

| シーン | カーブの値 |
| --- | --- |
| イントロ | 0.5（全8bar） |
| ビルド | 8bar のとき 0.75。16bar のとき 1つ目 0.6、2つ目 0.75 |
| ドロップ | フェーズ1のカーブ（A 0.75, A' 0.9, B 0.5, A'' 1.0） |
| ブレイクダウン | 0.4（全8bar） |

ビルドを単調増加にし、フェーズ1のカーブ（B で 0.5 に落ちる）を掛けないのは、上昇の途中で谷を作らないためです。ビルドの上限をドロップの A（0.75）に揃えるのは、ドロップの頭でドラムがビルドより薄くならないようにするためです。ビルドの緊張の高まりは、エネルギーよりもライザーとハイパスのスイープで作ります。ドロップだけフェーズ1のカーブを使うのは、ドロップの32bar の中に A A' B A'' の起伏を残し、32bar の区切りを聴き取れるようにするためです。

### 主題の共有

サイクル内の4つの32bar は、1つの曲の中の各部分として、同じ主題を共有します。

| 要素 | 決めるタイミング | 共有する範囲 |
| --- | --- | --- |
| 主進行 | サイクルの頭。前のサイクルから確率 `m32` で替わる（フェーズ2の主進行の選択を32bar ごとから128bar ごとに移す） | サイクル内の A・A'・A'' |
| 転換進行 | 32bar の頭（フェーズ2のまま） | その32bar の B |
| 音程のあるパートの A・A'・A'' 用の型と乱数列 | サイクルの頭 | サイクル内の A・A'・A'' |
| 音程のあるパートの B 用の型と乱数列 | 32bar の頭（フェーズ2のまま） | その32bar の B |
| ドラムの基準パターン | サイクルの頭と、ドロップ2の頭で `m32` に従って強い変異 | 次に変異するまで |

これにより、ドロップ1とドロップ2の A・A'・A'' では、進行・リースベース・スタブ・パッドが同じ形で戻り、ドラムのグルーヴだけが変わります。B は32bar ごとに選び直す転換進行と型で鳴るので、ドロップごとに異なります。また、32bar の終わりの大きなフィルの長さ（16か32ステップ）は32bar ごとに選ぶので、A'' の最後の2bar では音程のあるパートの打ち切り位置が変わることがあります。サブベースはキックに従うので、新しいグルーヴに合わせてリズムが変わります。イントロとブレイクダウンにも同じ主題が（パートを抜いた形で）流れるので、サイクル全体が1曲としてまとまって聞こえます。

`m32` が 0 のときは、主進行も基準パターンも最初のまま変わりません（フェーズ2と同じ意味）。

### シーンの境界のフィル

| 境界 | フィル |
| --- | --- |
| イントロ → ビルド（8bar 境界） | 8bar の終わりのフィルを必ず入れる。種類と長さはフェーズ1のまま |
| ビルド → ドロップ（32bar 境界） | 大きなフィルを、スネアロール・加速ロール・後半ロールから選ぶ。長さは従来どおり16か32ステップ。最後の1拍（ステップ 28〜31）は溜めとし、ドラムのフィルも含めて全パートを鳴らさない。パッドも溜めの頭で止める（後述） |
| ドロップ → ブレイクダウン（32bar 境界） | 大きなフィル（フェーズ2のまま） |
| ブレイクダウン → ビルド（8bar 境界） | 8bar の終わりのフィルを必ず入れ、種類はスネアロールとする。長さは従来どおり選ぶ。ブレイクダウンで抜いているドラムのうち、このフィルのスネアだけは鳴らし、ドラムが戻ってくることを予告する |
| ドロップ2 → 次のサイクルのイントロ（32bar 境界） | 大きなフィル（フェーズ2のまま） |

**溜めの中の音**: 溜めの中で鳴ってよいのは、リバーブの残響（リバーブスローを含む）とライザーの消え際だけです。パッドのノートは溜めの頭で終わるように長さを決めますが、パッドのリリース（約 1.2 秒）は174 BPM の1拍（約 0.34 秒）より長く、そのままでは溜めを埋めてしまいます。そのため再生側で、溜めの頭でパッドを短いフェードで切ります。

フィルの種類を選ぶ乱数の引き方は変えず、選ぶ表だけをシーンの境界に応じて差し替えます。ドロップの前をロール系に限るのは、ドロップアウトやゴーストラッシュでは、溜めの前に緊張が上がりきらないためです。

### FX

すべての FX は、生成側で2bar ごとのイベントとして決めます。2bar をまたぐ FX は、その2bar 内の区間（開始ステップ、終了ステップ、開始時と終了時の進み具合）に分けて出します。進み具合はシーン内の位置だけから決まるので、どの2bar から見ても同じ値になり、乱数は使いません。

**ライザー**: ビルドの頭から溜めの直前（ドロップの1拍前）までを進み具合 0 → 1 とし、ホワイトノイズのバンドパスの中心周波数と音量を上げていきます。溜めの頭で鳴り止みます。音が止まった後に残る無音と、リバーブスローの残響が溜めになります。

**インパクト**: ドロップの頭（ステップ0）で1回鳴らします。ピッチが下がるサイン波とノイズのバーストを重ねた合成音です。キック・サブベースと同じ瞬間に低域が重なるため、インパクトの低域はサブベースの帯域より上で鳴らすか十分に下げ、N-10（クリップしない）を満たすようにします。具体的な音色は設計書で決めます。

**リバーブスロー**: ドロップとブレイクダウンの直前の2bar で、最後に鳴るスネアの打音1つを、通常のセンドとは別の経路でリバーブに大きく送ります。ドロップの前では溜めの直前のスネア、ブレイクダウンの前では32bar の最後のスネアです。スネアが鳴らない（大きなフィルがドロップアウトなど）ときはスローしません。

**フィルタースイープ**: マスターのコンプレッサーの前に、ハイパスとローパスを1つずつ置きます。

| シーン | 動き |
| --- | --- |
| イントロ | ローパスを閉じた状態から、イントロの最後の8bar の頭までに開ききる |
| ビルド | ハイパスを開いた状態（可聴域の下端）から、溜めの頭まで上げ続ける |
| ドロップの頭 | ハイパスとローパスを開いた状態に戻す |
| それ以外 | 開いたまま動かさない |

周波数の範囲とカーブは設計書で決めます。周波数は対数的に動かし、耳で聞いて一定の速さで変わるようにします。

### データ構造

```ts
type CycleIndex = Brand<number, 'CycleIndex'>;   // 再生開始からの128bar の数
type PhraseIn128 = 0 | 1 | 2 | 3;

// サイクルのレイアウト。ビルドの長さは 4 − イントロ（ブレイクダウン）の長さから決まり、別に持たない
interface CycleLayout {
  readonly introSections: 2 | 3;
  readonly breakdownSections: 2 | 3;
}

// シーン内の8bar の位置。長さと位置を組にし、長さを超える位置を表現できないようにする
type LeadPosition  = { sections: 2; index: 0 | 1 } | { sections: 3; index: 0 | 1 | 2 };
type BuildPosition = { sections: 1; index: 0 } | { sections: 2; index: 0 | 1 };

// シーンは判別共用体にし、シーンごとに意味のある情報だけを持たせる
type SceneRole =
  | ({ scene: 'intro' } & LeadPosition)
  | ({ scene: 'build' } & BuildPosition)   // 直後は必ずドロップ
  | { scene: 'drop'; drop: 'first' | 'second' }
  | ({ scene: 'breakdown' } & LeadPosition);

// Context に追加するもの。コンダクターが作る
interface ArrangementContext {
  readonly cycle: CycleIndex;
  readonly phraseIn128: PhraseIn128;
  readonly layout: CycleLayout;
  readonly sceneRole: SceneRole;
}

// 2bar 内の区間。progress はシーン内の進み具合（0〜1）
interface FxSpan { from: Step; to: Step; startProgress: UnitInterval; endProgress: UnitInterval }

interface RiserSegment { fx: 'riser'; span: FxSpan }
interface Impact       { fx: 'impact'; step: Step }
interface ReverbThrow  { fx: 'throw'; step: Step }                       // 対象はスネアだけ
interface SweepSegment { fx: 'sweep'; filter: 'lowpass' | 'highpass'; span: FxSpan }
interface FilterReset  { fx: 'filterReset'; step: Step }                 // ドロップの頭
type FxEvent = RiserSegment | Impact | ReverbThrow | SweepSegment | FilterReset;
```

`SceneRole` と、`Context` がすでに持つ8bar の役割（`sectionRole`）との対応は、`phraseIn128` とレイアウトから一意に決まります。食い違う組を作れないよう、コンダクターだけが両方を作ります。

ミキサーの設定に、FX のチャンネル `fx: SendingChannel` を加えます。

### シードの派生

フェーズ2までの派生はすべて引き継ぎ、次を加えます（タグの値は19から）。キーとミキサーの設定はどのシードにも混ぜません。

- サイクル: `cycle = hash(master, TAG.cycle, サイクルの番号)`
- レイアウト: `hash(cycle, TAG.layout)`。イントロの長さ、ブレイクダウンの長さの順に引く
- 主進行: `hash(cycle, TAG.progression)`。変化の判定、主進行の順に引く
- 転換進行: フェーズ2のまま `hash(phrase, TAG.progression)` から引く。主進行の選択に使っていた2つの値は、引いたうえで使わない（乱数の引き方を変えないため）
- 音程のあるパートの型: A・A'・A'' 用は `hash(cycle, TAG.xxxStyle)` から型の表全体で選ぶ。B 用は `hash(phrase, TAG.xxxStyle)` から、そのサイクルの A 用の型を除いた残りで選ぶ（F-38 を保つため）
- 音程のあるパートの A・A'・A'' のフレーズ: `hash(cycle, TAG.xxxRhythm / xxxPitch, REL[pairRelation])`。B はフェーズ2のまま `section` から派生する
- ドラムの強い変異: フェーズ1のまま `hash(phrase, TAG.mutate32, パート番号)`。変異を行う32bar だけで使う
- FX は乱数を使わない

## パラメーター仕様

新しい生成パラメーターは加えません。既存のパラメーターは、次の点だけ意味が変わります。

| 名前 | キー | フェーズ3での効き方 |
| --- | --- | --- |
| 32bar 変化率 | `m32` | サイクルの頭での主題（主進行）の交替の確率と、サイクルの頭とドロップ2の頭での強い変異の量 |
| エネルギーの起伏 | `energyDepth` | シーンのカーブにかける深さ。0 のとき全シーンでエネルギーが1になる（パートの出し入れと FX は残る） |
| フィル強度 | `fillIntensity` | 0 のとき、シーンの境界の必須フィルも、大きなフィルも入らない。溜めとリバーブスローは残る |

**ミキサー**に FX のチャンネルを加えます。範囲と表示は他のチャンネルと同じです。既定値は設計書で決め、試聴で確定します。

シーンの表（パート構成・エネルギー）、レイアウトの確率、FX の音色とスイープの範囲、リバーブスローの送り量は UI に出さず、設定ファイルの定数として持ちます。

## 非機能要件

MVP からフェーズ2までの N-01〜N-11 を、FX とオートメーションを含めて引き継ぎます。N-03 の「2bar 分の生成処理が 5ms 以内」は、アレンジと FX の生成を含めた合計で満たします。

| ID | 区分 | 要件 |
| --- | --- | --- |
| N-12 | 性能 | 全パートと FX、スイープ用のフィルターを既定のミキサー設定で鳴らしても、MVP と同じ環境で処理落ちによる音切れが起きないこと |
| N-13 | 音質 | ドロップの頭（インパクト・キック・サブベースが重なる瞬間）を含め、既定の設定でリミッターの後の出力が 0 dBFS を超えないこと |
| N-14 | 再現性 | 同じシードとパラメーターなら、シーンの並び、FX のイベント、オートメーションの値が一致すること。ミキサーの操作でこれらが変わらないこと |

## 受け入れ基準

自動テストと試聴、長時間動作の3つを満たした時点でフェーズ3完了とします。

**自動テスト**

- [ ] MVP からフェーズ2までの自動テストの受け入れ基準を、変更点の表で改めたものも含めて、フェーズ3の生成器ですべて満たす
- [ ] すべてのサイクルで、シーンの並びが F-52・F-53 のレイアウトのいずれかに従い、ドロップが32bar 境界で始まり、ビルドの直後が必ずドロップになる
- [ ] 4通りのレイアウトがすべて現れる（4096bar のシミュレーション）
- [ ] 各シーンで鳴らさないパートのイベントが1つもない（ブレイクダウンの最後のフィルのスネアを除く）
- [ ] ビルドのエネルギーが単調に増えてドロップの A を超えず、ドロップのエネルギーがフェーズ1のカーブに従う。`energyDepth = 0` のとき全シーンでエネルギーが1になる
- [ ] 主進行がサイクルの頭以外で変わらず、`m32 = 0` では最初の主進行のまま変わらない
- [ ] 同じサイクルのドロップ1とドロップ2の A・A'・A'' で、進行が一致し、大きなフィル区間より前のリースベース・スタブ・パッドのイベント列が一致する
- [ ] 転換の8bar の音程のあるパートの型が、そのサイクルの A の型と異なる
- [ ] ドラムの基準パターンが変わるのが、サイクルの頭とドロップ2の頭だけである
- [ ] ドロップ直前の大きなフィルがロール系で、ステップ 28〜31 で鳴っている音がない（全イベントで `step + length ≤ 28`。ドラムは発音位置が 28 未満）
- [ ] シーンが変わる8bar の終わりで、`fillIntensity > 0` なら必ずフィルが入る
- [ ] インパクトがドロップの頭のステップ0にだけある
- [ ] ライザーの区間がビルドの中にだけあり、途切れずにつながり、進み具合が単調に増えて溜めの頭で終わる
- [ ] スイープのローパスはイントロにだけ、ハイパスはビルドにだけあり、ドロップの頭でリセットされる
- [ ] リバーブスローが、ドロップとブレイクダウンの直前の2bar にだけあり、その2bar で最後に鳴るスネアの位置にある
- [ ] 同じシードで2回生成したとき、ノートと FX のイベントが一致する
- [ ] 2bar 生成処理（アレンジと FX を含む合計）の平均が 5ms 以内

**試聴（1時間）**

低域の評価はヘッドホンかモニタースピーカーで行います。

- [ ] 1時間の中で、展開の起伏を感じる。単調に感じて聞き流してしまう時間帯がない
- [ ] シーンの切り替わりが、唐突ではなく自然に聞こえる
- [ ] ビルドで緊張が高まり、溜めからドロップの頭で解放される感覚がある
- [ ] ドロップ2で、ドロップ1の主題が戻ってきたと分かり、かつグルーヴの変化で新鮮さがある
- [ ] ブレイクダウンが間延びせず、ドラムが戻る予告（スネアロール）が効いている
- [ ] FX が他のパートを覆い隠さず、ドロップの頭を含めてクリップの表示が一度も点かない
- [ ] 2bar ごとのコードの変化とシーンの起伏があっても、32bar の区切りを指摘できる
- [ ] 停止と再生を繰り返しても、前の再生の FX やフィルターの状態が残らない

**長時間動作**

- [ ] FX とオートメーションを含めた1時間連続再生で、メモリ使用量が安定している

## 未決事項

実装前に確認したい点と、試聴で決める点です。

- イントロをサイクルごとに戻す（ドロップ2の後に中くらいのエネルギーに落とす）か、再生開始時だけにしてサイクルを「ドロップ1 → ブレイクダウン＋ビルド → ドロップ2 → （中間のシーン）＋ビルド」のように組むか。本書は前者を採り、ドラムを残したイントロで DJ ミックスのようにつなぐ
- 主題を128bar で共有し、ドロップ2で主題を再現する方式の是非。採らない場合は、フェーズ2のまま32bar ごとに `m32` で主題が変わり、同じシードのドラムと音程のあるパートがフェーズ2と一致する
- シーンごとのエネルギーの値と、レイアウトの確率（試聴で決める）。特に、ビルドの上限をドロップの A に揃えたことで、ビルドの終盤の密度が物足りなくならないか
- ライザーを溜めの頭で止めるか、ドロップの頭まで鳴らすか（試聴で決める）
- イントロのローパスをミックス全体にかけるか、ドラム以外にだけかけるか。ドロップ2から次のサイクルのイントロに移るとき、ドラムまでこもると落差が大きすぎる可能性がある（試聴で決める）
- ドロップ2をドロップ1より盛り上げるための追加の変化（エネルギーカーブを上げる、スタブの型を選び直すなど）が必要か（試聴で決める）
