# MVP要件定義書

## 目的とスコープ

MVPの目的は「ドラムだけで10分間飽きずに聴けるビートを生成できるか」を検証することです。特に、2bar と 8bar の階層的な変化が耳で聴き取れ、かつ破綻しないことを確認します。

**MVPに含むもの**

- ドラム4パート（キック、スネア、ハイハット、ゴーストスネア）のサンプル再生
- 2bar 基本パターンの生成と、8bar 境界での変異
- 2bar 単位の装飾と、8bar の終わりのフィル
- シード付き乱数による再現可能な生成
- Tone.js の Transport による途切れない再生
- 最小限の操作パネル（再生/停止、BPM、変化率、シード）
- 音声なしで長時間生成して統計を出すシミュレーションツール

**MVPに含まないもの（後続フェーズ）**

- 32bar の区間の関係（反復・変奏・転換）とエネルギーカーブ（フェーズ1）。ただしコンダクターは32bar内の位置を最初から計算し、後付けで設計が変わらないようにします
- ベース、ウワモノ、FX、シーン構成
- サブジャンル別プリセット、URL 共有、音声書き出し、MIDI 出力、ユーザーサンプル、モバイル対応（現時点ではロードマップの対象外）

## システム構成

MVP は「生成」と「再生」の2領域に分かれ、Tone.js の Transport が2bar ごとに生成側へ次のイベント列を要求します。

生成側は Tone.js（Web Audio）に依存しないため、シミュレーションツールや単体テストから同じ生成器をそのまま呼べます。

## 機能要件

| ID | 区分 | 要件 | 優先度 |
| --- | --- | --- | --- |

| F-02 | 再生 | 停止後に再生すると、同じシードなら最初から同じ展開を再現する | 必須 |
| F-03 | 再生 | 再生中の BPM 変更は受け付けず、BPM は停止中のみ変更できる（MVP 以降も同じ方針） | 必須 |
| F-04 | 構造 | コンダクターが小節カウンタから、2bar 内・8bar 内・32bar 内の位置と終端フラグを持つコンテキストを生成する | 必須 |
| F-05 | 生成 | 2bar（16分×32ステップ）の基本パターンを、ステップ重み表に基づいて生成する | 必須 |
| F-06 | 生成 | スネアはフィル区間を除き、2拍目・4拍目の頭（バックビート）だけで鳴らし、変異の対象外とする | 必須 |

| F-08 | 生成 | 各2bar の2小節目後半に、確率に基づく装飾を重ねる。装飾は次の2bar に持ち越さない | 必須 |
| F-09 | 生成 | 8bar の終わりにフィルを生成する。長さは8小節目の最後の1拍・2拍・1小節、または7〜8小節目の2小節 | 必須 |

## 生成ロジック仕様

生成は「基本パターン（持続）＋装飾（一時）＋フィル（一時）」の重ね合わせで、2bar ごとに1回実行します。基本パターンを書き換えるのは8bar 境界の変異だけです。

### データ構造

```ts
type Part = 'kick' | 'snare' | 'hat' | 'ghost';

// 2bar = 16分 × 32ステップ。値はベロシティ（0 = 無音、0〜1）
type Pattern = Record<Part, number[]>; // 各配列の長さは32

interface NoteEvent {
  step: number;      // 0〜31
  part: Part;
  velocity: number;  // 0〜1
}

interface Context {
  bar: number;               // 通算小節（0始まり）
  pairIn8: 0 | 1 | 2 | 3;    // 8bar 内の何番目の2bar か
  sectionIn32: 0 | 1 | 2 | 3;// 32bar 内の何番目の8bar か
  isSectionStart: boolean;   // 8bar の頭（変異のタイミング）
  isSectionEnd: boolean;     // 8bar の最後の2bar（フィルのタイミング）
  relation: 'repeat' | 'variant'; // 8bar の基準に対する関係（反復・反復・反復・変奏）
  seeds: { section: number; ornament: number; fill: number };
  params: Params;
}

interface Generator {
  generate(ctx: Context): NoteEvent[]; // 次の2bar 分
}
```

### ステップ重み表

パートごとに32ステップ分の「鳴りやすさ」（0〜1）を持ちます。変異・装飾はこの表からサンプリングするため、ランダムでも DnB の文法から外れません。各ステップは4段階に分類します。

| 分類 | 重み | キックの例（1小節16ステップ中） | 用途 |
| --- | --- | --- | --- |
| アンカー | 1.0（固定） | 0 | 常に鳴る。変異で消さない |
| 主候補 | 0.5〜0.8 | 10 | 典型的な2ステップの位置 |
| 副候補 | 0.1〜0.3 | 3, 7, 11, 14 | 変化をつける位置 |
| 禁止 | 0 | 4, 12（スネアと衝突） | 生成しない |

スネアは4と12（2拍目・4拍目）がアンカーで、それ以外はすべて禁止です。ゴーストは7, 9, 15 などスネア前後を主候補にします。

ハイハットだけは2bar 分の重み表を持たず、1拍（4ステップ）分の重み `[0.5, 0.1, 0.8, 0.2]` から1拍のパターンを作り、それを2bar に8回繰り返します。32ステップ全体で自由に生成すると、まとまりがなくなるためです。

### 変異（8bar 境界）

1. パートごとに変異回数を決める: 期待値 `x = m8 × 変異しやすさ[part] × そのパートの発音数` の小数部分を確率として切り上げる（x = 0.42 なら 42% で1回、58% で0回）。ハイハットの発音数は1拍のパターン内で数える
   - `round(x)` では x < 0.5 が常に0回になり、発音数が減ったパートが二度と変異しなくなるため
   - 切り上げ判定の乱数は、小数部分が0でも必ず1回引く
2. 1回ごとに「追加」「削除」「移動（±1〜2ステップ）」のいずれかを、重み表に従って選んで適用する。ハイハットは1拍のパターンに対して適用する
3. 制約（アンカー維持、キックとスネアの非衝突、パート別の最小・最大発音数）を満たすか確認し、満たさなければ最大10回まで引き直す。それでも駄目なら変異を取り消す
4. 結果を新しい基本パターンとして保存する

変異しやすさの既定値は、キック 0.4、スネア 0（変異しない）、ハイハット 0.8、ゴースト 1.0 です。

### 装飾（2bar ごと）

2小節目の後半（ステップ24〜31）で、ハイハットとゴーストに限り `確率 = m2 × 重み[step]` で音を足します。ベロシティは 0.3〜0.6 とし、基本パターンには保存しません。乱数は `seeds.ornament` から引くため、反復の2bar では同じ装飾が再現されます。

同じ8bar 内で反復の関係にある2bar は、ベース・装飾とも完全に一致させます。これは次の3点で担保します。

- 基本パターンは8bar 境界でしか書き換わらない
- 装飾の乱数は2bar ごとに `seeds.ornament` から新しく初期化し、直前の2bar の乱数列を引き継がない
- 装飾に効くパラメーター（`m2`）は8bar 境界でのみ反映する

別の8bar では `seeds.section` が変わるため、同じ反復でも中身は異なります。

### フィル（8bar の終わり）

`isSectionEnd` のとき、フィル強度の確率で、8bar の終わりをテンプレートから選んだフィルに置き換えます。長いフィルは特別感を保つため低い確率にします。

| 長さ | 範囲 | 確率 |
| --- | --- | --- |
| 4ステップ | 8小節目の4拍目 | 40% |
| 8ステップ | 8小節目の3〜4拍目 | 40% |
| 16ステップ | 8小節目全体 | 15% |
| 32ステップ | 7〜8小節目全体 | 5% |

フィル区間では、テンプレートが残すパート以外をすべて消し、テンプレートの音を足します。残すパートは、フィルがないときと同じ音（基本パターンと装飾）で鳴ります。MVP のテンプレートは次の6種類で、均等に選びます。

| 種類 | 残すパート | 足す音 |
| --- | --- | --- |
| スネアロール | なし | 全ステップにスネア（16分、ベロシティ漸増） |
| ゴースト連打 | スネア（バックビート） | バックビート以外の全ステップにゴースト（ベロシティ漸増） |
| ドロップアウト | なし | なし（スネアも含めて完全に無音） |
| キックソロ | キック | なし |
| スネアソロ | スネア | なし |
| ハットソロ | ハイハット | なし |

ドロップアウトとソロでは、フィル区間のバックビートも鳴りません（F-06 の例外）。

### シードの派生

マスターシードから決定的に派生させます（hash は整数ハッシュ関数）。

- `section = hash(master, 'section', 8bar の通し番号)`
- `ornament = hash(section, relation)` … 反復の3回は同じ値、変奏だけ異なる
- `fill = hash(section, 'fill')`

## パラメーター仕様

UI で操作できるパラメーターは以下の6つです。変化率（m2 / m8）の既定値は、MVP 完了後の調整期間を経て m2 = 0.3、m8 = 0.35 で確定しました。フィル強度とマスター音量の既定値は、フェーズ2 完了後にフィル強度を 0.7 から 0.3 へ、マスター音量を 0.8 から 0.5 へ変更しました。

| 名前 | キー | 範囲 | 既定値 | 反映タイミング |
| --- | --- | --- | --- | --- |
| BPM | `bpm` | 160〜180 | 174 | 停止中のみ変更可（再生中は固定） |
| 2bar 変化率 | `m2` | 0〜1 | 0.3 | 次の8bar 境界 |
| 8bar 変化率 | `m8` | 0〜1 | 0.35 | 次の8bar 境界 |
| フィル強度 | `fillIntensity` | 0〜1 | 0.3 | 次の8bar の7〜8小節目 |
| マスター音量 | `volume` | 0〜1 | 0.5 | 即時 |
| シード | `seed` | 32bit 整数 | ランダム | 停止→再生時 |

パートごとの変異しやすさとステップ重み表は、MVP では UI に出さず、設定ファイルの定数として持ちます。

## 非機能要件

| ID | 区分 | 要件 |
| --- | --- | --- |
| N-01 | タイミング | 発音は Transport のコールバックが渡す時刻で予約し、聴感上のズレや揺れがないこと（目安: 誤差 1ms 未満） |
| N-02 | タイミング | タブを切り替えたりメインスレッドが一時的に重くなったりしても、音が途切れないこと（Tone.js の lookAhead を基準に調整） |
| N-03 | 性能 | 2bar 分の生成処理が 5ms 以内に終わること |
| N-04 | 安定性 | 連続1時間再生してもメモリ使用量が増え続けないこと（再生済みノードの解放） |
| N-05 | 再現性 | 同じシード・同じパラメーター操作なら、生成されるイベント列が完全に一致すること |
| N-06 | 対応環境 | デスクトップ版 Chrome / Firefox / Safari / Edge の最新版で動作すること |
| N-07 | 保守性 | 生成器は Tone.js（Web Audio）に依存せず、Node.js 上で単体テストできること |

## 受け入れ基準

自動テストと試聴の両方を満たした時点で MVP 完了とします。

**自動テスト**

- [x] 同じシードで2回生成した4096小節分のイベント列が完全に一致する
- [x] フィル区間を除く全小節で、スネアが2拍目・4拍目の頭だけで鳴っている
- [x] キックとスネアのアンカー以外の衝突が0件
- [x] 装飾が次の2bar に持ち越されていない
- [x] 基本パターンの変化が8bar 境界でのみ起きている
- [x] 2bar 生成処理の平均が 5ms 以内
- [x] 同じ8bar 内で反復の2bar（3回）のイベント列がすべて一致する

**試聴（10分）**

- [x] 10分間、聴き手が「同じループの繰り返し」とも「無秩序」とも感じない
- [x] 8bar の区切りを聴き手が指摘できる
- [x] テンポの揺れや音切れを感じない
- [x] 既定値で破綻した（DnB に聞こえない）区間がない

**長時間動作**

- [x] 1時間連続再生でメモリ使用量が安定している

## 未決事項

- ドラムサンプルの入手元とライセンス（自作か、ロイヤリティフリー素材か）
- 試聴評価の具体的な方法（評価シートの形式、評価者の選定）
- 反復率の定義（何をもって「同じ2bar」とみなすか）と、目標とする数値の範囲
