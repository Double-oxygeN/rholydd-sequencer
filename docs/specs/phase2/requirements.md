# フェーズ2要件定義書（ハーモニー、ウワモノとミックス）

## 目的とスコープ

フェーズ2の目的は、ドラムとサブベースの上にコード進行と3つのウワモノ（リースベース、スタブ、パッド）を重ね、ミックスを整えたうえで、次の3点を検証することです。

- 調性が破綻しない
- ベースとキックの低域がぶつからない
- 全パートを同時に鳴らしても、音割れや処理落ちが起きない

**フェーズ2に含むもの**

- コンダクターによるコード進行の生成（2bar に1コード、8bar で4コードの進行）
- コード進行に合わせたサブベースの音高
- リースベース、スタブ、パッドの生成器と、Tone.js のシンセによる合成音源
- パート別ミキサー（音量・パン・ミュート・リバーブのセンド）と、センド/リターン構成のリバーブ（Tone.Reverb）
- ドラムバスとマスターのコンプレッサー（Tone.Compressor）、最終段のリミッター（Tone.Limiter）、マスターのクリップ検出
- キックをトリガーにしたサイドチェインで、サブベース・リースベース・パッドをダッキング
- 上記に伴う操作パネル・表示・シミュレーションツールの拡張

**フェーズ2に含まないもの（後続フェーズ）**

- FX、シーン構成（フェーズ3）。8bar の役割やシーンに応じてパートを出し入れするのもシーンで扱う。フェーズ2では、ミュートしたパートを除き全パートが常に鳴る
- ベースのグライド（ポルタメント）。フェーズ2の完了条件の検証に必要ないため。リースベースを試聴してから検討する（未決事項を参照）
- ナチュラルマイナー以外の旋法、ダイアトニックコード以外の和音（借用和音、セカンダリードミナントなど）、9th などのテンションを含むボイシング
- エフェクトのパラメーター（リバーブの長さ、コンプレッサーのスレッショルドなど）の UI。設定ファイルの定数として持つ
- ミキサー設定の保存とプリセット
- [設計コンセプト](../../design/beats.md) の32bar の行にある「ハット/ライド」の切り替えと「ブレイク素材」（フェーズ1から持ち越し。未決事項を参照）

## フェーズ1要件からの変更点

MVP とフェーズ1の要件は、ここに挙げたもの以外すべて引き継ぎます。

| 対象 | フェーズ1 | フェーズ2 |
| --- | --- | --- |
| 反復の一致（MVP の受け入れ基準、フェーズ1の「反復の一致」） | 同じ8bar 内の反復の2bar は、ベースを含めてイベント列が完全に一致する | ドラムのイベント列は完全に一致する。音程のあるパートは、発音位置・長さと、コードのルートからの音度が一致する。2bar ごとにコードが変わり、音高そのものは一致しないため |
| F-23 ベースの音高 | 中心音は A・A'・A'' で主音、B で ♭6・♭7・4 のいずれか。音度の重みは中心音からの音階上の距離 0, 2, 3, 4, 5, 6 に付ける | 中心音はその2bar のコードのルート。音度はコードトーン（距離 0, 2, 4, 6）だけから選ぶ。距離 3・5 はコードによって非和声音になるため外す |
| B の中心音 | ベースの型の乱数列から3つ目に引く | 引かない。B の中心音の移動は転換進行が担う |
| F-25 停止 | ベースは停止時にドラムと同時に止まる | 全パート、リバーブの残響、予約済みのダッキングが同時に止まる |
| F-30 キー | キーはベースの音高の移調だけに効く | 音程のある全パートの移調だけに効く。コード進行の選択も乱数の引き方も変えない |
| `Context` | 構造とパラメーター | コンダクターが選んだ8bar の進行を加える |
| `NoteEvent` | ドラムの打音とベースのノート | リースベース、スタブ、パッドを加える。ベースが2つになり `'bass'` では区別できないため、サブベースの `instrument` を `'sub'` に改める |
| `volume` | マスター音量 | リミッターの後に置く聴取音量。パート別の音量はミキサーで扱う |

ドラムの生成と、ドラムに関わるシードの派生は変えません。同じシードなら、ドラムはフェーズ1と同じ展開になります。サブベースはリズムが同じで、音高だけがコード進行に従って変わります。

## システム構成

MVP 以来の「生成」と「再生」の分離を保ちます。生成側は2bar ごとに次の順で進みます。

1. コンダクターが、32bar 内の位置、エネルギー、8bar の進行を含む構造のコンテキストを作る
2. ドラム生成器が、構造のコンテキストからドラムの確定結果を作る
3. 構造のコンテキストにドラムの確定結果を加えたコンテキストを作る
4. サブベース・リースベース・スタブ・パッドの各生成器が、そのコンテキストからノートを作る

音程のある4パートは互いの出力を参照しません。調性の一貫性は、全パートが同じコードのコードトーンだけを鳴らすことで保ちます。パート同士を参照させると生成の順序に依存関係が生まれ、パートの追加や削除のたびに既存パートの結果が変わるためです。同じ理由で、パートごとに別々の乱数列を使い、パートを足しても既存パートの乱数列は変えません。

この順序は、フェーズ1と同じくアンサンブルの1か所にまとめます。

再生側の信号の流れは次のとおりです。

```
kick  ──────────────▶ [ch] ─┐
snare ──────────────▶ [ch] ─┤
hat   ──────────────▶ [ch] ─┼─▶ ドラムバス（Comp）─┐
ghost ──────────────▶ [ch] ─┘                      │
sub   ─▶ [ダッキング] ─▶ [ch] ─────────────────────┤
reese ─▶ [ダッキング] ─▶ [ch] ─────────────────────┼─▶ マスター（Comp ─▶ Limiter）─▶ クリップ検出 ─▶ 音量 ─▶ 出力
stab  ──────────────▶ [ch] ────────────────────────┤
pad   ─▶ [ダッキング] ─▶ [ch] ─────────────────────┤
          [ch] のセンド ─▶ リバーブ ─▶ [リターン] ──┘
```

`[ch]` はミキサーのチャンネル（ミュート・音量・パン）で、センドは音量の後から取ります。

ミキサーとダッキングの設定は再生側だけに効かせ、アンサンブルの入力にしません。ミュート中のパートも生成は続け、ミュートを解除するとその時点の続きから鳴ります。ミキサーの操作で同じシードの展開が変わらないようにするためです（N-05）。

ダッキングのトリガーには、実際に鳴るキック（ドラムの確定結果の打音にあるキック）を使います。サブベースのリズムに使う「フィルを適用する前のキック」は使いません。キックを消すフィル（スネアロール、ドロップアウトなど）の間はキックが鳴らないので、ダッキングもしません。キックソロのフィルでは、鳴るキックごとにダッキングします。

## 生成ロジック仕様

### コード

コードはキーのナチュラルマイナーの各音にスケール上の3度を3つ重ねた4和音で、ルートの音度だけで決まります。構成音はすべて音階内の音なので、コードトーンだけを鳴らす限り音階外の音は出ません。

| 度数 | F マイナーでの例 | 構成音 |
| --- | --- | --- |
| i | Fm7 | F, A♭, C, E♭ |
| III | A♭maj7 | A♭, C, E♭, G |
| iv | B♭m7 | B♭, D♭, F, A♭ |
| v | Cm7 | C, E♭, G, B♭ |
| VI | D♭maj7 | D♭, F, A♭, C |
| VII | E♭7 | E♭, G, B♭, D♭ |

ii（Gm7♭5）は使いません。ルートと5度が減5度になり、サブベースが5度を選ぶと低域で三全音が鳴るためです。

### 進行

8bar の進行は、8bar 内の2bar（`pairIn8` = 0〜3）に1つずつ割り当てる4コードです。進行は次の表から均等に選びます。

**主進行**（A・A'・A''。i で始める）

| # | 進行 |
| --- | --- |
| 1 | i – VI – III – VII |
| 2 | i – VII – VI – VII |
| 3 | i – iv – VI – VII |
| 4 | i – VI – iv – v |
| 5 | i – i – VI – VII |
| 6 | i – III – VII – VI |

**転換進行**（B。i 以外で始める）

| # | 進行 |
| --- | --- |
| 1 | VI – VII – i – i |
| 2 | iv – v – VI – VII |
| 3 | VI – III – VII – VII |
| 4 | iv – VI – VII – VII |
| 5 | VI – VII – iv – v |

A・A'・A'' で同じ進行を繰り返し、B で i 以外から始まる進行に移すのは、フェーズ1で試聴して確定した「A に戻る感覚」（A 系の中心音は主音、B だけ ♭6・♭7・4 に移す）を和声でも保つためです。転換進行の多くを VI か iv で始めるのも、フェーズ1の B の中心音に合わせています。主進行と転換進行は表が別なので、B の進行は必ず A と異なります。

**32bar 境界での主進行の変化**: 最初の32bar では主進行を表から選びます。以降の32bar の頭では乱数を1回引き、`m32` 未満なら現在の主進行以外の5つから選び直し、それ以外は引き継ぎます。主進行が替わるのは32bar 境界だけです。転換進行は32bar ごとに表から選びます。乱数は、替えるかどうかにかかわらず「変化の判定」「主進行の選択」「転換進行の選択」の3つをこの順に引きます。

主進行を `m32` で引き継ぐのは、ドラムの基準パターンと同じく、32bar の変化の量を1つのパラメーターでまとめて操作できるようにするためです。

### サブベース（F-23 の改訂）

リズム（型、重み、キックへの加点、音の長さ、大きなフィルの扱い、32bar ごとの型の選択）はフェーズ1のまま変えません。音高だけを次のように改めます。

- 中心音はその2bar のコードのルートとし、各2bar の最初のノートは中心音にする
- 音度は、中心音からの音階上の距離で次の重みから選ぶ

| 距離 | 0（ルート） | 2（3度） | 4（5度） | 6（7度） |
| --- | --- | --- | --- | --- |
| 重み | 0.5 | 0.1 | 0.15 | 0.1 |

重みはフェーズ1の値から、距離 3・5 を除いたものです。音域（F1〜E2 に折り返し）とオクターブ跳躍（確率 0.2 で F2〜E3）はフェーズ1のまま変えません。

### リースベース

リースベースは、サブベースより細かいリズムで中域を動かす役割です。サブベースの帯域はハイパスで切って重ねず、低域の骨格はサブベースに任せます。

**音域**: F2（MIDI 41）〜 E3（MIDI 52）。すべての音をこの範囲に折り返し、跳躍はしません。

**リズムの型**: 4種類です。キックへの加点は持ちません。キックとの関係はダッキングで整えます。

| 型 | 発音しやすい位置 |
| --- | --- |
| サステイン | ステップ16 |
| 8分ロール | 8分の位置（偶数ステップ） |
| シンコペーション | 16分の裏（ステップ 3, 6, 10, 19, 22, 26） |
| 応答 | 2小節目後半の16分（ステップ 24〜31） |

型ごとに32ステップ分の重み表を持ち、ステップ0 はすべての型でアンカーです。ステップ `s` の発音しやすさは `重み[s] × E`（アンカーは1）とし、全ステップで乱数を1回ずつ引きます。エネルギーが低い8bar では動きが減り、サステインに近づきます。具体的な重みは設計書で決めます。

**音の長さ**: サブベースと同じく、次の発音の直前（最後の音は2bar の終わりか、大きなフィルの開始の直前）まで伸ばします。

**音高**: 中心音はコードのルートで、各2bar の最初のノートは中心音にします。それ以外の音は、中心音からの音階上の距離で選びます。

| 距離 | 0（ルート） | 2（3度） | 4（5度） | 6（7度） |
| --- | --- | --- | --- | --- |
| 重み | 0.6 | 0.1 | 0.2 | 0.1 |

**32bar の構造との対応**: サブベースと同じです。32bar の頭で A・A'・A'' 用の型を4種類から均等に1つ選び、B 用の型を残りの3種類から選びます。A・A'・A'' は32bar ごとに共通の乱数列を使い、B だけ別の乱数列を使います。

### スタブ

スタブは、コードを短く切って鳴らすウワモノです。

**ボイシング**: コードのルートを除く3音（3度・5度・7度）を、それぞれ C4（MIDI 60）〜 B4（MIDI 71）に折り返して同時に鳴らします。ルートを除くのは、サブベースとリースベースが鳴らすルートを重ねず、中高域を薄く保つためです。

**長さ**: 2ステップ（8分）で一定です。

**リズムの型**: 4種類です。ステップ 4, 12, 20, 28（スネアのバックビート）の重みはどの型でも0にし、スネアの抜けを妨げないようにします。

| 型 | 発音しやすい位置 |
| --- | --- |
| 裏拍 | 8分の裏（ステップ 2, 6, 10, 14, 18, 22, 26, 30） |
| 付点 | ステップ 0, 6, 16, 22 |
| まばら | ステップ 6, 22 |
| 応答 | 2小節目後半（ステップ 24, 26, 30） |

アンカーは持たず、2bar に1回も鳴らないこともあります。ステップ `s` の発音しやすさは `重み[s] × E` とし、全ステップで乱数を1回ずつ引きます。前の音と重なる位置（直前の発音から2ステップ未満）では発音しません。具体的な重みは設計書で決めます。

**32bar の構造との対応**: リースベースと同じく、A・A'・A'' 用と B 用の型を32bar ごとに選び、B の型は A と異なるものにします。

### パッド

パッドは、各2bar のコードの4音を、ステップ0 から32ステップ（2bar 全体）鳴らします。乱数は使わず、進行だけから決まります。

**音域**: F3（MIDI 53）〜 E5（MIDI 76）。

**ボイシング**: 8bar の最初のコードは、構成音を下から順に積んだ形（転回なし）を、音域の中央に最も近くなるオクターブに置きます。8bar 内の2つ目以降のコードは、音域内の転回形のうち、直前のコードからの各声部の移動量の合計が最小になるものを選びます。ボイシングを8bar ごとに決め直すのは、前の8bar の状態に依存させず、8bar の頭からいつでも同じ結果を再現できるようにするためです。

**フィル**: 32bar の終わりの大きなフィル区間でも鳴らし続けます。サブベースとリースベースが止まる間に和声を残し、次の32bar へのつながりを保つためです。

### ダッキング（サイドチェイン）

Tone.Compressor にはサイドチェイン入力がないため、キックのイベントからゲインのエンベロープを予約して模擬します。キックの時刻は2bar 分前もって分かっているので、キックの発音の時点で下げきっておけます。

- 実際に鳴るキックごとに、ゲインを数ミリ秒で `1 − ダッキング量 × パートの比` まで下げ、ダッキングの戻り時間をかけて1に戻す
- 戻りきる前に次のキックが来たら、その時点の値から下げ直す
- パートの比は定数で、既定値はサブベース 1.0、リースベース 0.7、パッド 0.5 とする

エンベロープの時刻と値は Tone.js に依存しない関数で求め、単体テストで検証できるようにします。

### ミキサーとダイナミクス

- ミキサーの各チャンネルは、ミュート → 音量 → パンの順に通し、センドは音量の後から取る
- キックとサブベースはパンとセンドを持たない。低域をモノラルに保ち、リバーブで低域を濁らせないため
- ドラムバスとマスターのコンプレッサー、リミッターのパラメーターは定数とする。リミッターのスレッショルドは −1 dB とする
- Tone.Limiter は、レシオ20・アタック3ms のコンプレッサーで、ブリックウォールリミッターではありません。速い立ち上がりで 0 dBFS を超える可能性が残るため、リミッターの後でクリップを検出して表示する（F-46）
- クリップ検出は全サンプルを検査する。Tone.Meter のように平滑化した値を画面の更新周期で読むと、短いピークを見逃し、タブが背景にあると更新自体が間引かれるため
- 聴取音量（`volume`）はクリップ検出の後に置く。聴く音量を下げてもクリップの検出結果が変わらないようにするため

### データ構造

```ts
// ii を除くダイアトニックコードのルート（音階の何番目の音か）
type ChordRoot = 0 | 2 | 3 | 4 | 5 | 6;   // i, III, iv, v, VI, VII
interface Chord { root: ChordRoot }        // 構成音はルートから音階上で 0, 2, 4, 6 番目

// i で始まるかどうかを型で区別し、主進行と転換進行を取り違えられないようにする
type MainProgression       = readonly [{ root: 0 }, Chord, Chord, Chord];
type TransitionProgression = readonly [{ root: Exclude<ChordRoot, 0> }, Chord, Chord, Chord];

// Context に追加するもの。コンダクターが作る
interface HarmonyContext {
  // その2bar のコードは progression[pairIn8] で求める。コードを別に持つと進行と食い違う状態を表現できてしまうため
  progression: MainProgression | TransitionProgression;
}

type Pitch = Brand<number, 'Pitch'>;   // MIDI ノート番号。音域はパートごとに決める
type Voicing = readonly Pitch[];        // 同時に鳴らす音。低い順

interface DrumHit  { instrument: 'drums'; step: Step; part: Part; velocity: Velocity; layer: Layer }
interface SubNote  { instrument: 'sub';   step: Step; length: StepLength; pitch: Pitch; velocity: Velocity }
interface ReeseNote { instrument: 'reese'; step: Step; length: StepLength; pitch: Pitch; velocity: Velocity }
interface StabHit  { instrument: 'stab';  step: Step; length: StepLength; voicing: Voicing; velocity: Velocity }
interface PadChord { instrument: 'pad';   step: Step; length: StepLength; voicing: Voicing; velocity: Velocity }
type NoteEvent = DrumHit | SubNote | ReeseNote | StabHit | PadChord;

// 再生側だけで使う設定。アンサンブルの入力にはしない
type Decibels = Brand<number, 'Decibels'>;
type Pan = Brand<number, 'Pan'>;               // −1（左）〜 1（右）
type Milliseconds = Brand<number, 'Milliseconds'>;
interface Channel        { level: Decibels; muted: boolean }
interface PannedChannel  extends Channel { pan: Pan }
interface SendingChannel extends PannedChannel { send: UnitInterval }
// キックとサブベースにパンとセンドを持たせないことを型で表す
interface MixerSettings {
  kick: Channel; sub: Channel;
  snare: SendingChannel; hat: SendingChannel; ghost: SendingChannel;
  reese: SendingChannel; stab: SendingChannel; pad: SendingChannel;
  reverbReturn: Channel;
}
interface DuckingSettings { depth: UnitInterval; release: Milliseconds }
```

ベロシティは、サブベース 0.8（フェーズ1のまま）、リースベース 0.8、スタブ 0.7、パッド 0.6 で一定とします。パート間の音量差はミキサーで扱います。

### シードの派生

フェーズ1の派生はすべて引き継ぎ、次を加えます。キーとミキサーの設定はどのシードにも混ぜません。

- 進行: `hash(phrase, TAG.progression)`。変化の判定、主進行、転換進行の3つをこの順に引く
- リースベースの型: `hash(phrase, TAG.reeseStyle)`。A 用、B 用の順に引く
- リースベースのリズム: サブベースと同じく、A・A'・A'' は `hash(phrase, TAG.reeseRhythm, REL[pairRelation])`、B は `hash(section, TAG.reeseRhythm, REL[pairRelation])`
- リースベースの音高: A・A'・A'' は `hash(phrase, TAG.reesePitch, REL[pairRelation])`、B は `hash(section, TAG.reesePitch, REL[pairRelation])`
- スタブの型: `hash(phrase, TAG.stabStyle)`。A 用、B 用の順に引く
- スタブのリズム: A・A'・A'' は `hash(phrase, TAG.stabRhythm, REL[pairRelation])`、B は `hash(section, TAG.stabRhythm, REL[pairRelation])`
- パッドは乱数を使わない

フェーズ1でベースの型の乱数列から引いていた B の中心音は、引かないようにします。最後に引いていた値なので、A 用・B 用の型の選択は変わりません。

## パラメーター仕様

フェーズ1の9つに、次の2つと、ミキサーの設定を加えます。

| 名前 | キー | 範囲 | 既定値 | 反映タイミング |
| --- | --- | --- | --- | --- |
| ダッキング量 | `duckDepth` | 0〜1 | 0.6 | 次の2bar の予約から |
| ダッキングの戻り時間 | `duckRelease` | 30〜300 ms | 100 ms | 次の2bar の予約から |

ダッキングは2bar ごとにまとめて予約するので、変更は次の2bar から反映します。

**ミキサー**（いずれも即時反映）

| 項目 | 範囲 | 表示 |
| --- | --- | --- |
| 各チャンネルの音量 | −40〜+6 dB | dB |
| パン | −1〜1 | L100〜C〜R100 |
| リバーブのセンド | 0〜1 | 百分率 |
| ミュート | オン/オフ | — |
| リバーブのリターンの音量 | −40〜+6 dB | dB |

ミキサーの既定値は設計書で決め、試聴で調整します。音量だけ dB で表示するのは、ミキサーの音量は比で扱うのが一般的で、0 dB（素通し）からの増減が分かりやすいためです。

`m32` は「32bar 境界での強い変異の量」に加えて、主進行が替わる確率にも効くようになります。既存のパラメーターの範囲と反映タイミングは変えません。

進行の表、各パートの音域・重み表、ダッキングのパートの比、リバーブの長さ、コンプレッサーとリミッターのパラメーター、シンセの音色は UI に出さず、設定ファイルの定数として持ちます。

## 非機能要件

MVP とフェーズ1の N-01〜N-08 を、全パートとエフェクトを含めて引き継ぎます。N-03 の「2bar 分の生成処理が 5ms 以内」は全パートの合計で満たします。

| ID | 区分 | 要件 |
| --- | --- | --- |
| N-09 | 性能 | 全パートとエフェクトを既定のミキサー設定で鳴らしても、MVP と同じ環境で処理落ちによる音切れが起きないこと |
| N-10 | 音質 | 既定のミキサー設定とパラメーターで、リミッターの後の出力が 0 dBFS を超えないこと（F-46 のクリップ検出で確認する） |
| N-11 | 再現性 | ミキサーとダッキングの設定を再生中にどう操作しても、生成されるイベント列が変わらないこと |

## 受け入れ基準

自動テストと試聴、長時間動作の3つを満たした時点でフェーズ2完了とします。

**自動テスト**

- [x] MVP とフェーズ1の自動テストの受け入れ基準を、変更点の表で改めたものも含めて、フェーズ2の生成器ですべて満たす
- [x] すべての8bar で、A・A'・A'' の進行が主進行の表に、B の進行が転換進行の表に含まれ、同じ32bar の A・A'・A'' の進行が一致する
- [x] 主進行が替わるのが32bar 境界だけで、`m32 = 0` では最初の主進行のまま変わらない
- [x] サブベース・リースベース・スタブ・パッドのすべての音が、その2bar のコードの構成音で、パートごとの音域に収まる
- [x] 同じシードでキーだけを変えたとき、音程のある全パートが移調した音高になり、ドラムと進行（度数）は一致する
- [x] 同じ8bar 内の反復の2bar（3回）で、ドラムのイベント列が一致し、音程のある各パートの発音位置・長さ・ルートからの音度が一致する
- [x] サブベース・リースベース・スタブのノートが2bar をまたがず、32bar の終わりの大きなフィル区間にない。パッドは大きなフィル区間でも鳴る
- [x] 8bar の終わりのフィルの有無や種類を変えても、ドラム以外のノート列が変わらない
- [x] スタブがステップ 4, 12, 20, 28 で鳴らない
- [x] 転換の8bar のリースベースとスタブの型が、同じ32bar の A の型と異なる
- [x] ダッキングのエンベロープが、実際に鳴るキックの時刻ごとに下がり、キックが鳴らない区間では下がらない
- [x] クリップ検出が、0 dBFS を1サンプルだけ超える信号を検出し、0 dBFS 未満の信号では検出しない
- [x] 2bar 生成処理（全パートの合計）の平均が 5ms 以内

**試聴（30分）**

- [ ] 30分間、コードとベース・ウワモノがぶつかって濁る（調性が破綻したと感じる）箇所がない
- [ ] キックがサブベースに埋もれず、低域がぶつからない。ダッキングが不自然なポンピングに聞こえない
- [ ] 全パートを同時に鳴らして、音割れや音切れを感じず、クリップの表示が一度も点かない
- [ ] 2bar ごとにコードが変わっても、32bar の区切りを指摘できる
- [ ] 停止と再生を繰り返しても、前の再生の音やダッキングが残らない
- [ ] 既定値で破綻した（DnB に聞こえない）区間がない

**長時間動作**

- [ ] 全パートとエフェクトを含めた1時間連続再生で、メモリ使用量が安定している

## 未決事項

- 進行の表の妥当性と、主進行を `m32` で引き継ぐ方式でよいか（試聴で見直す）
- ダッキング量・戻り時間・パートの比と、ミキサーの既定値（試聴で確定する）
- ゲインエンベロープの予約で自然さが足りない場合に、Tone.Follower によるエンベロープフォロワーへ切り替えるか
- ベースのグライド。リースベースで特に効果が大きいため、フェーズ2の試聴後に扱うフェーズを決める
- 同じコードが続く2bar（例: i – i）で、パッドを弾き直さずにつなぐか
- 処理落ちの確認方法。ブラウザ間で共通に使える音声スレッドの負荷の指標がないため、試聴と Performance パネルで確認する
- 「ハット/ライド」の切り替えと「ブレイク素材」を扱うフェーズ（フェーズ1から持ち越し）
- 32bar の終わり以外の8bar の終わりに、16・32ステップの長いフィルを残すかどうか（フェーズ1から持ち越し）
- エネルギーカーブ、`m32`・`energyDepth` の既定値の妥当性（フェーズ1から持ち越し。ウワモノを加えた状態で見直す）
- 試聴環境: 低域の評価はヘッドホンかモニタースピーカーで行う
