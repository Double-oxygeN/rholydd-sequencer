# フェーズ1要件定義書（32bar 構造とベース）

## 目的とスコープ

フェーズ1の目的は、ドラムだけで成立した2bar・8bar の変化の作法の上に32bar の階層を重ね、固定キーのサブベースを加えても全体が破綻しないことを検証することです。特に、32bar の区切りが耳で聴き取れること、ベースとキックの低域がぶつからないことを確認します。

**フェーズ1に含むもの**

- 32bar の区間の関係（反復・変奏・転換・変奏）と、32bar 境界での強い変異
- 32bar の終わり（31〜32小節目）の大きなフィル
- 32bar 単位のエネルギーカーブ（密度のマクロ制御）
- 固定キーのサブベース（合成音源）。リズムはキックから派生させる
- 上記に伴う操作パネル・表示・シミュレーションツールの拡張

**フェーズ1に含まないもの（後続フェーズ）**

- コード進行、リースベース、スタブ、パッド、ミキサー、リバーブ、コンプレッサー、サイドチェイン（フェーズ2）
- FX、シーン構成（フェーズ3）
- [設計コンセプト](../../design/beats.md) の32bar の行にある「ハット/ライド」の切り替えと「ブレイク素材」。ロードマップのフェーズ1の項目になく、パートとサンプルの追加を伴うため（未決事項を参照）

## MVP要件からの変更点

MVP要件定義書の要件は、ここに挙げたもの以外すべて引き継ぎます。

| 対象 | MVP | フェーズ1 |
| --- | --- | --- |
| F-07 変異 | 8bar 境界ごとに変異を累積し、以降の基準にする | 基準パターンを書き換えるのは32bar 境界の強い変異だけ。8bar 境界の変異は「基準からの変奏」として毎回基準から作り直す |
| F-09 フィル | すべての8bar の終わりで同じ規則 | 32bar の終わりだけ、大きなフィルの規則に置き換える |
| `Relation` | `'repeat' \| 'variant'` | 2bar 用と8bar 用に分け、8bar 用には `'transition'`（転換）を加える |
| `NoteEvent` | ドラムの4パートのみ | ドラムの打音とベースのノートの判別共用体にする |
| `Generator` | `generate(ctx)` のみ | ベースは `ctx` に加えて、同じ2bar のドラムの確定結果（キックの位置とフィル区間）を受け取る |
| シードの派生 | 8bar の通し番号から直接派生 | 32bar（フレーズ）のシードを挟んで派生 |

シードの派生が変わるため、同じシードでもMVPとは異なる展開になります。MVP との互換は保ちません。

## システム構成

MVP の「生成」と「再生」の分離を保ちます。生成側では、コンダクターが32bar 内の位置とエネルギーを含むコンテキストを作り、ドラム生成器、ベース生成器の順に呼びます。

ベースのリズムはキックから派生させるため、ベース生成器だけは同じ2bar のドラムの確定結果を入力に取ります。ドラムの生成規則を複製してキックの位置を予測する方法は、ドラム側の変更でずれるため採りません。そのため、ロードマップのリスク対策にある「全パートがコンダクターのコンテキストだけを参照」は、「コンテキストと、依存先パートの同じ2bar の確定結果だけを参照」に改めます。依存は一方向（ドラム → ベース）に限ります。

## 生成ロジック仕様

### 32bar の区間の関係

32bar は8bar×4 で、1つ目の8bar を基準（A）とし、残りを基準に対する関係で作ります。

| 32bar 内の8bar | 役割 | 表示 | 基本パターン |
| --- | --- | --- | --- |
| 0 | 反復 | A | 基準パターンそのもの |
| 1 | 変奏 | A' | 基準に8bar の変異（`m8`）をかけたもの |
| 2 | 転換 | B | 重み表から新しく生成したもの |
| 3 | 変奏 | A'' | 基準に8bar の変異（`m8`）をかけたもの。A' とは別のシード |

変奏と転換を基準から毎回作り直し、累積させないのは、A に戻る感覚（A A' B A''）で32bar のまとまりを聴き取れるようにするためです。基準そのものは32bar 境界でだけ変わるので、長時間の展開は32bar ごとの強い変異が担います。

各8bar の中の2bar の関係（反復・反復・反復・変奏）と装飾・フィルの規則は MVP のまま変えません。

### 強い変異（32bar 境界）

MVP の変異と同じ手順で、変異回数の期待値を `x = m32 × 強い変異しやすさ[part] × そのパートの発音数` とします。強い変異しやすさの既定値は、キック 1.0、スネア 0（変異しない）、ハイハット 1.0、ゴースト 1.0 です。最初の32bar の基準は MVP と同じく重み表から生成します。

### 転換

転換の8bar の基本パターンは、MVP の初期生成と同じ方法で重み表から作ります。キックのモチーフが基準と一致した場合は、最大10回まで引き直し、それでも一致する場合は基準に強い変異をかけたものを使います。転換は一時的な変化で、基準には書き戻しません。

### 大きなフィル（32bar の終わり）

32bar の最後の2bar（31〜32小節目）では、MVP のフィル判定の代わりに次の規則を使います。

- フィル強度が0より大きければ必ず鳴らす（0なら鳴らさない）
- 長さは16ステップ（32小節目全体）が 60%、32ステップ（31〜32小節目全体）が 40%
- テンプレートは MVP のスネアロール・ゴースト連打・ドロップアウトに、次の2種類を加えた5種類から均等に選ぶ

| 種類 | 残すパート | 足す音 |
| --- | --- | --- |
| 加速ロール | なし | 前半は8分、後半は16分のスネア（ベロシティ漸増） |
| ドロップからロール | なし | 前半は完全に無音、後半は16分のスネア（ベロシティ漸増） |

32bar の終わり以外の8bar の終わりのフィルは MVP のまま（16・32ステップの長いフィルも低確率で残す）とします。

### エネルギーカーブ

32bar 内の8bar ごとに、エネルギー `E`（0〜1）を次の式で決めます。

```
E = 1 − energyDepth × (1 − curve[sectionIn32])
curve = [0.75, 0.9, 0.5, 1.0]   // A, A', B, A''
```

`energyDepth = 0` なら常に `E = 1` で、MVP と同じ密度になります。カーブは転換で下げ、最後の8bar で最大にして、大きなフィルから次の32bar の頭へつなげます。

エネルギーは8bar の頭で決め、その8bar の間は変えません。同じ8bar 内で反復の2bar を完全に一致させる MVP の規則を守るためです。

`E` は次の2か所に効かせます。

1. **間引き**: キック・ハイハット・ゴーストのアンカー以外の発音を、確率 `(1 − E) × (1 − 重み)` で鳴らさない。重みの低い位置から抜けていくので、DnB の骨格は残る。パート別の最小発音数を下回る場合は、重みの高い順に戻す。間引きは基本パターンには書き戻さない
2. **装飾**: 装飾の確率を `m2 × 重み[step] × E` にする

間引きの乱数は、発音の有無にかかわらずモチーフの全位置で1回ずつ引きます。

### ベース

**キー**: F ナチュラルマイナー（F, G, A♭, B♭, C, D♭, E♭）に固定します。音域は F1（MIDI 29）〜 E2（MIDI 40）の1オクターブで、すべての音をこの範囲に折り返します。

**リズム**: 同じ2bar のドラムの確定結果から、キックの発音ステップ `k1 < k2 < … < kn` を取り出し、次のノートを作ります。

- キック `ki` ごとに、ステップ `ki + guard` から `k(i+1)`（最後のキックは2bar の終わり）の直前までを1つのノートとする。`guard` はキックの低域を守る保護区間で、既定値は1ステップ（16分）
- 長さが `guard` 以下で、ノートにならない区間は鳴らさない
- 8ステップ以上のノートは、確率 0.3 で途中の8分の位置から2音に分ける。2音目の音高は音度表から選ぶ
- フィル区間（キックソロを除く）ではノートをフィル開始の直前で切り、フィル区間内には置かない

2bar の頭（ステップ0）のキックはアンカーで必ず鳴るため、ベースのノートが2bar をまたぐことはありません。

**音高**: 音度ごとの重みから選びます。各2bar の最初のノートは中心音とします。

| 音度 | 1 | ♭3 | 4 | 5 | ♭6 | ♭7 |
| --- | --- | --- | --- | --- | --- | --- |
| 重み | 0.5 | 0.1 | 0.05 | 0.15 | 0.1 | 0.1 |

中心音は、反復と変奏の8bar では主音（F）とし、転換の8bar では ♭6・♭7・4 のいずれかに移します。反復と変奏の8bar は32bar ごとに共通の音度列を使い、転換の8bar だけ別の音度列を使います。ベースの形でも A に戻る感覚を出すためです。

**反復の一致**: 同じ8bar 内の反復の2bar では、キックが一致するのでベースも完全に一致させます。音度列の乱数は2bar ごとに作り直し、変奏の2bar だけ別のシードを使います（装飾と同じ規則）。

**ベロシティ**: 0.8 で一定とします。音量差による聴き取りやすさの調整はフェーズ2のミキサーで扱います。

### データ構造

```ts
type PairRelation = 'repeat' | 'variant';                     // 8bar 内の2bar
type SectionRelation = 'repeat' | 'variant' | 'transition';   // 32bar 内の8bar

// sectionIn32 から一意に決まる値を、矛盾した組み合わせにできないよう判別共用体にする
type SectionRole =
  | { sectionIn32: 0; relation: 'repeat';     isPhraseStart: true;  isPhraseEnd: false }
  | { sectionIn32: 1; relation: 'variant';    isPhraseStart: false; isPhraseEnd: false }
  | { sectionIn32: 2; relation: 'transition'; isPhraseStart: false; isPhraseEnd: false }
  | { sectionIn32: 3; relation: 'variant';    isPhraseStart: false; isPhraseEnd: true };

// MVP の Context に追加するもの
interface PhraseContext {
  phrase: PhraseIndex;          // 32bar の通し番号
  sectionRole: SectionRole;
  energy: UnitInterval;         // 8bar の頭でラッチ
  seeds: { phrase: Seed; section: Seed; ornament: Seed; fill: Seed; bass: Seed };
}

type Pitch = Brand<number, 'Pitch'>;          // MIDI ノート番号。29〜40
type StepLength = Brand<number, 'StepLength'>; // 1〜32。ノートの長さ（16分単位）

interface DrumHit  { instrument: 'drums'; step: Step; part: Part; velocity: Velocity; layer: Layer }
interface BassNote { instrument: 'bass';  step: Step; length: StepLength; pitch: Pitch; velocity: Velocity }
type NoteEvent = DrumHit | BassNote;

// ベースが依存するドラムの確定結果
interface KickGuide {
  kicks: readonly Step[];        // フィル適用後のキックの発音ステップ
  bassCutFrom: Step | null;      // ベースを止めるフィルの開始ステップ（キックソロでは null）
}
```

### シードの派生

- `phrase = hash(master, TAG.phrase, 32bar の通し番号)`
- `section = hash(phrase, TAG.section, sectionIn32)`
- `ornament = hash(section, REL[pairRelation])`、`fill = hash(section, TAG.fill)` は MVP のまま
- 強い変異: パートごとに `hash(phrase, TAG.mutate32, パート番号)`
- 変奏の変異: パートごとに `hash(section, TAG.mutate, パート番号)`（MVP のまま）
- 転換: `hash(phrase, TAG.transition)`
- 間引き: パートごとに `hash(section, TAG.thin, パート番号)`
- ベースの音度列: 反復・変奏の8bar は `hash(phrase, TAG.bass, REL[pairRelation])`、転換の8bar は `hash(section, TAG.bass, REL[pairRelation])`
- 2音への分割: `hash(section, TAG.split, REL[pairRelation])`

MVP と同じく、タグは整数の定数とし、乱数は用途ごとに別々に作り、条件によらず先に引いてから判定します。

## パラメーター仕様

MVP の6つに、次の2つを加えます。

| 名前 | キー | 範囲 | 既定値 | 反映タイミング |
| --- | --- | --- | --- | --- |
| 32bar 変化率 | `m32` | 0〜1 | 0.6 | 次の32bar 境界 |
| エネルギーの起伏 | `energyDepth` | 0〜1 | 0.5 | 次の8bar 境界 |

既存のパラメーターの反映タイミングは MVP のまま変えません。`m8` の意味は「8bar ごとに累積する変化の量」から「基準に対する変奏の量」に変わります。

キー、音域、`guard`、エネルギーカーブ、強い変異しやすさ、大きなフィルの確率は UI に出さず、設定ファイルの定数として持ちます。

## 非機能要件

MVP の N-01〜N-07 をベースを含めて引き継ぎます。N-03 の「2bar 分の生成処理が 5ms 以内」は、ドラムとベースの合計で満たします。

| ID | 区分 | 要件 |
| --- | --- | --- |
| N-08 | タイミング | ベースのノートオフ（リリースの減衰を含む）が、次のキックの発音時刻より前に終わること |
| N-09 | 性能 | ベースを加えても、MVP と同じ環境で音切れが起きないこと |

## 受け入れ基準

自動テストと試聴、長時間動作の3つを満たした時点でフェーズ1完了とします。

**自動テスト**

- [ ] MVP の自動テストの受け入れ基準を、フェーズ1の生成器ですべて満たす
- [ ] 基準パターンの変化が32bar 境界でのみ起きている
- [ ] 変奏の8bar の基本パターンが、同じ32bar の基準パターンにその8bar のシードで1回だけ変異をかけたものと一致する（変奏が累積しない）
- [ ] すべての転換の8bar で、キックのモチーフが基準と異なる
- [ ] フィル強度が0でない限り、すべての32bar の終わりに16または32ステップのフィルがある
- [ ] 同じ8bar 内でエネルギーが変わらない。`energyDepth = 0` のとき間引きが起きない
- [ ] `energyDepth = 1` で4096小節生成したとき、8bar の役割ごとの平均密度は B が最も低く、A'' が最も高い
- [ ] キックの保護区間（発音ステップから `guard` ステップ）とベースのノートの重なりが0件
- [ ] ベースのすべての音が F ナチュラルマイナーの音で、F1〜E2 に収まる
- [ ] ベースのノートが2bar をまたがず、フィル区間（キックソロを除く）にない
- [ ] 同じ8bar 内で反復の2bar（3回）のベースのノート列がすべて一致する
- [ ] 2bar 生成処理（ドラムとベースの合計）の平均が 5ms 以内

**試聴（30分）**

- [ ] 30分間、聴き手が32bar の区切りを指摘できる
- [ ] ベースとキックの低域がぶつからない（濁りや打ち消し合いを感じない）
- [ ] 転換の8bar が、別の曲ではなく同じ曲の展開として聴こえる
- [ ] テンポの揺れや音切れを感じない
- [ ] 既定値で破綻した（DnB に聞こえない）区間がない

**長時間動作**

- [ ] ベースを含めた1時間連続再生で、メモリ使用量が安定している

## 未決事項

- 32bar の関係の解釈: 本書は基準を保持する A A' B A'' としたが、MVP のように変異を累積させ、転換の後の変奏は転換から作る解釈もありうる
- ベースがドラムの確定結果を参照する方式と、それに伴うロードマップのリスク対策の書き換え
- キー（F マイナーを暫定値とした）と音域
- 「ハット/ライド」の切り替えと「ブレイク素材」を扱うフェーズ
- `guard`、エネルギーカーブ、`m32`・`energyDepth` の既定値の妥当性（シミュレーションと試聴で見直す）
- 32bar の終わり以外の8bar の終わりに、16・32ステップの長いフィルを残すかどうか（大きなフィルが目立たなければ外す）
- 試聴環境: サブベースはノートPCのスピーカーでは聴こえにくいため、ヘッドホンかモニタースピーカーで評価する
