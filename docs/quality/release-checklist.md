# リリースの確認

自動のテストで確かめられない確認（試聴・UI・ブラウザ・アクセシビリティ・長時間の動作）と、リリースの手順です。リリースのたびにこの一覧を写し、結果をリリースのプルリクエストか Issue に記録します。

## 準備

- 低域の評価は、ヘッドホンかモニタースピーカーで行う。サブベースはノートPCのスピーカーでは聞こえにくいため
- 試聴は既定の設定（設定ファイルなし）で行う。クリップしないことと試聴の確認を保証するのは既定値だけのため
- 試聴の前に、変えた数値の効き方をシミュレーションで確かめておく（[テスト](./testing.md#シミュレーション)）
- スマートフォンの確認は、配布したページ（https）で行うのが確実。配布の前に開発中のコードを試すときは、README の「スマートフォンで試す」の手順で、安全な接続で開く

## 試聴（1時間）

**ビートと構成**

- [ ] 「同じループの繰り返し」とも「無秩序」とも感じない
- [ ] 8bar と32bar の区切りを指摘できる。2bar ごとのコードの変化とシーンの起伏があっても、32bar の区切りが分かる
- [ ] B（転換）の8bar が、別の曲ではなく同じ曲の展開として聞こえる
- [ ] テンポの揺れや音切れを感じない
- [ ] 既定値で、DnB に聞こえない区間がない

**アレンジ**

- [ ] 展開の起伏を感じ、単調に感じて聞き流してしまう時間帯がない
- [ ] シーンの切り替わりが、唐突ではなく自然に聞こえる
- [ ] ドロップ2から次のサイクルのイントロに移るとき、曲が止まったようには聞こえず、次の曲に移ったと感じる
- [ ] ビルドで緊張が高まり、溜めからドロップの頭で解放される感覚がある
- [ ] 4つの入り方のどれでも、ドロップの頭の着地が分かる。ドロップの入りが毎回同じに聞こえない
- [ ] ドロップ2で、ドロップ1の主題が戻ってきたと分かり、かつグルーヴの変化で新鮮さがある
- [ ] 64bar のドロップが間延びしない
- [ ] ブレイクダウンが間延びせず、ドラムが戻る予告（スネアロール）が効いている
- [ ] どのイントロの入り順でも、ドロップ2からイントロに移るとき、曲が止まったようには聞こえず、次の曲に移ったと感じる
- [ ] `hats` と `kick` の最初の8bar で拍を見失わない
- [ ] イントロでスネアが入る8bar の頭が、予告のスネアロールで分かる（フィルがあるとき）
- [ ] 入り順が替わったことが、イントロの最初の8bar で分かる。24bar のイントロで、パートが段階的に入って聞こえる
- [ ] 一時停止と再開で、イントロの途中からでも同じ編成で鳴る

**和声**

- [ ] コードとベース・上モノがぶつかって濁る箇所がない。テンションと借用和音が調性を崩さず、ベースと濁らない
- [ ] 借用和音が、唐突ではなく色合いの変化として聞こえる。V7 から i への解決が自然に聞こえる
- [ ] 和声の色合いが単調に聞こえない
- [ ] サイクルの頭の移調が唐突に聞こえず、移調したサイクルで響きの色合いが変わったと感じる

**音とミックス**

- [ ] キックがサブベースに埋もれず、低域がぶつからない。ダッキングが不自然なポンピングに聞こえない
- [ ] 音色が替わったサイクルで、別の曲に移ったと感じる。同じ型や進行が戻ってきても、音色の違いで新鮮に聞こえる
- [ ] 音色の切り替えでクリックやノイズが出ず、前のサイクルの余韻の音色が途中で変わらない
- [ ] どの音色でも、そのパートが他のパートに埋もれず、突出もしない。リースベースがサブベース・キックとぶつからない
- [ ] FX が他のパートを覆い隠さない
- [ ] 全パートと FX を、音色の組み合わせを替えながら、スペクトラムアナライザーを表示したまま鳴らしても、ドロップの頭を含めてクリップの表示が一度も点かず、処理落ちによる音切れがない
- [ ] ソロにしたパートとその残響だけが聞こえ、ソロを解除すると元のミックスに戻る
- [ ] クラッシュのどの位置も区切りとして聞こえ、多すぎない
- [ ] ドロップの頭で、インパクト・キック・サブベース・クラッシュが重なっても、クリップの表示が点かない
- [ ] クラッシュがハイハットとスタブを覆い隠さず、余韻がドラムバスのコンプレッサーで不自然に揺れない
- [ ] ライドのどの型も、ドロップ2に新鮮さを足し、ハイハットとぶつからない
- [ ] 合成したクラッシュとライドが、DnB のシンバルとして聞こえる

**再生の操作**

- [ ] 停止と再生を繰り返しても、前の再生の音・ダッキング・FX・フィルターの状態が残らない
- [ ] 一時停止から再開すると、止めた位置から途切れずに続く。ビルドの途中、溜めの中、ドロップの頭の直後で一時停止しても、ライザー・ハイパス・パッドの状態が自然につながる
- [ ] 一時停止と再開で、クリックやノイズが出ない
- [ ] 2bar の途中で一時停止してすぐに再開しても、一時停止の前に予約された音が二重に鳴らない。クラッシュが二重に鳴らない

**リファクタリングの後**（生成を変えるつもりのない変更をしたリリース）

- [ ] 前のリリースと同じシードで聴き比べて、音・ミキサー・一時停止と再開・FX に違いが聞こえない

## UI

- [ ] 初期画面に、ロゴマークと見出し・再生と停止のボタン・音量・累計の表示・2行のメーター・シーケンサーかスペクトラムアナライザーのどちらか・共有のボタン・メニューを開くボタンだけが並ぶ
- [ ] 再生と一時停止のボタンが見えている幅では、メニューを開いたまま再生・一時停止でき、メニューが閉じるボタンでだけ閉じる
- [ ] スペクトラムアナライザーで、低域のキックとサブベース、高域のハイハットの動きを見分けられる
- [ ] `?seed=12345` で開き直すと同じ展開になる
- [ ] 共有でコピーした URL を開くと、シードを含めたときは同じシード（再生中は鳴っていた展開のシード）、含めないときは乱数のシードで始まる
- [ ] `public/config.json` に BPM とミキサーの値を書いて開くと、パネルとミキサーにその値が出る。ファイルを消して開き直すと既定値に戻る
- [ ] 再生中にミキサーを動かしてから「ミキサーを既定値に戻す」を押すと、音もクリックやノイズなしに元のミックスに戻る。「パラメーターを既定値に戻す」の後は、次の区切りから元の変化の量に戻る

- [ ] メディア操作（OS のメディアキー、ロック画面、通知）から再生・一時停止・再開・停止でき、画面のボタンの表示と食い違わない。ロック画面・通知・デスクトップのメディアの表示に、アプリのアイコンが出る
- [ ] 共有のコピーができる（できないときは、選択して手でコピーするよう促される）
- [ ] 狭い画面（スマートフォン、またはデスクトップの開発者ツールで幅 320px と 375px）で、横にはみ出さず、ロゴマーク・見出し（欠けずに、必要なら2行で）・共有とメニューのボタンが重ならずに見え、シーケンサー（1小節と8マスのメーター）・スペクトラムアナライザー・メニューの両方のタブ・共有のダイアログの全体が見える
- [ ] キーボードで操作できる

**ホーム画面への追加とオフライン**

- [ ] Android の Chrome で、ホーム画面に追加でき、そこから開いて、再生とメディア操作ができる
- [ ] iOS の Safari で、ホーム画面に追加し、そこから開いたとき、画面のロック・ほかのアプリへの切り替え・ロック画面からの再開が、Safari で開いたときと同じに振る舞う。違えば README の対応環境に制約として書く
- [ ] 一度開いた端末で、機内モードにして（デスクトップは開発者ツールでオフラインにして）開き直すと、開いて再生でき、設定ファイルの警告が出ない（Chrome・Firefox・Safari）
- [ ] 新しい版を配布した後、開いているタブは古い版のまま鳴り続け、タブをすべて閉じて開き直すと新しい版になる

**iOS の実機**: 次の振る舞いを確かめ、手当てできない違いを README の対応環境に書きます。

- [ ] 消音のスイッチを入れたときに音が止まるか
- [ ] 画面をロックしたときに音が止まるか。止まったときに、画面とメディア操作の表示が実際の音と合っているか
- [ ] ほかのアプリに切り替えたときに音が止まるか。戻ったときに再開できるか

## キーボードとスクリーンリーダー

- [ ] マウスを使わず、キーボードだけで、再生・一時停止・再開・停止、音量、表示の切り替え、メニューのすべてのパラメーターとミキサーの操作、共有を行える
- [ ] フォーカスの位置が常に見え、メニューに隠れた部品にフォーカスが移らない
- [ ] スクリーンリーダー（VoiceOver か NVDA）で、すべての操作部品の名前と状態が読み上げられる。状態表示とコピーの成否が読み上げられる
- [ ] 再生中に、ステップやメーターの更新が読み上げられない

## 英語の画面

- [ ] 画面の文言とアクセシブルな名前がすべて英語で、日本語のブラウザでは日本語のまま
- [ ] スクリーンリーダー（VoiceOver か NVDA）で、すべての操作部品の名前と状態が英語で読み上げられる
- [ ] メディア操作（ロック画面・通知）に「Seed 123」のようにシードが出る
- [ ] 幅 320px と 375px で、英語の文言が欠けたり重なったりしない

## 長時間の動作

- [ ] スペクトラムアナライザーを表示し、一時停止と再開を挟みながら1時間再生しても、メモリの使用量が安定している（ブラウザの開発者ツールで、最初と最後のヒープを比べる）
- [ ] 再生中にタブを隠し（別のタブに切り替える、ウィンドウを最小化する、スマートフォンで画面を消す）、30 分鳴らしてから戻ったとき、画面が固まらずにすぐ今の位置を表示し、ヒープが隠す前より増え続けていない（Chrome・Firefox・Safari）

## リリースの手順

1. 上の確認を終え、結果を記録する
2. `npx playwright test --repeat-each 10` がすべて通ることを確かめる
3. `package.json`（と `package-lock.json`）の `version` を上げる
4. README を、リリースの時点の内容（対応環境と制約を含む）に更新する
5. main にマージし、CI が通って GitHub Pages に配布されたことを確かめる
6. 配布したページで、サンプルが読み込まれて再生でき、共有する URL が配布先の URL（`https://gh.double-oxygen.net/rholydd-sequencer/`）になることを確かめる。配布した URL を OGP の確認ツールか SNS・チャットに貼り、名前・説明・画像のプレビューが出ることを確かめる
7. main に `v` で始まるタグを付けて push し、GitHub Releases に利用者目線のリリースノートを書く。同じシードの展開が変わるときは、そう書く

**リポジトリの設定**（最初の配布の前に一度）

- リポジトリの Settings → Pages で、Source を「GitHub Actions」にする
- 無料のプランでは、GitHub Pages を使うにはリポジトリを公開する
- ユーザーのサイトに独自ドメイン（`gh.double-oxygen.net`）が設定してあるので、このリポジトリに `CNAME` は置かない
