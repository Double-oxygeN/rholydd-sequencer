# 品質の要件

機能の規則とは別に、アプリが満たし続けるべき性質と、その確かめ方をまとめます。確かめ方の詳細は [テスト](./testing.md) と [リリースの確認](./release-checklist.md) に書きます。

## タイミングと安定性

| 性質 | 内容 | 確かめ方 |
| --- | --- | --- |
| 予約どおりに鳴る | 発音は予約した時刻で鳴り、聴感上のズレや揺れがない（目安: 誤差 1ms 未満） | 試聴 |
| 途切れない | タブを切り替えたり、メインスレッドが一時的に重くなったりしても、音が途切れない | 試聴、ブラウザの確認 |
| メモリが増え続けない | スペクトラムアナライザーを表示し、一時停止と再開を挟みながら1時間再生しても、メモリの使用量が安定している | 長時間の動作の確認 |
| 処理落ちしない | 全パートと FX、スイープのフィルター、スペクトラムアナライザーを、どの音色の組み合わせで鳴らしても、処理落ちによる音切れが起きない | 試聴 |
| 起動に失敗しない | 設定ファイルがない、JSON として壊れている、値が不正、のいずれでも、コードの既定値か有効な値で起動する | 単体テスト、E2E テスト |

## 性能

| 性質 | 内容 | 確かめ方 |
| --- | --- | --- |
| 生成が速い | 2bar 分の生成（全パート、アレンジ、FX を含む）の平均が 5ms 以内 | `tests/quality/performance.test.ts` |
| 見ていない描画をしない | スペクトラムアナライザーは、表示している間だけ画面の更新に合わせて描画し、非表示・停止中・一時停止中は描画しない | 単体テストと試聴 |
| CI が速い | CI の1回の実行（3つのブラウザエンジンの E2E テストを含む）が10分以内に終わる | CI の実行時間 |

## 再現性

| 性質 | 内容 | 確かめ方 |
| --- | --- | --- |
| 同じ入力なら同じ展開 | 同じシード・パラメーターの操作・設定ファイルなら、イベント列・FX・シーンの並び・オートメーションの値・各サイクルの音色が完全に一致する | `tests/generation/baseline.test.ts` |
| ミキサーで展開が変わらない | ミキサー（ソロを含む）・ダッキング・音量をどう操作しても、生成されるイベント列が変わらない | 型（ミキサーの設定をアンサンブルに渡さない）と単体テスト |
| 初期キーで展開が変わらない | 初期キーを変えると、同じ展開を移調したものになる。移調の幅・色付け・音色は変わらない | 単体テスト |
| 一時停止で展開が変わらない | 一時停止と再開を何度繰り返しても、イベント列・FX・オートメーションの値が一時停止しなかった場合と一致する。長さとタイミングで変わらない | 単体テスト |
| 基準と一致する | 生成を変えるつもりのない変更の前後で、記録した基準と一致する | `tests/generation/baseline.test.ts` |

## 音質

| 性質 | 内容 | 確かめ方 |
| --- | --- | --- |
| クリップしない | 既定のミキサー設定とパラメーターで、ドロップの頭（インパクト・キック・サブベースが重なる瞬間）を含め、リミッターの後の出力が 0 dBFS を超えない | クリップの表示を見ながらの試聴 |
| クリックしない | 停止・一時停止・再開、ミキサーの操作、音色の切り替えで、クリックやノイズが出ない | 試聴 |

## 保守性

| 性質 | 内容 | 確かめ方 |
| --- | --- | --- |
| 生成をブラウザなしで動かせる | 生成は Tone.js（Web Audio）に依存せず、Node.js 上で単体テストとシミュレーションができる | 依存の向き、単体テスト |
| E2E テストが安定する | 音の出力やタイミングの揺れに左右されず、同じコードで繰り返し実行して毎回同じ結果になる | 10回の繰り返し実行 |
| 理由が文書から引ける | コードとテストのコメントは、フェーズの名前や要件の番号に頼らず、それだけで理由が分かる | `tests/quality/conventions.test.ts` |

## 対応環境

| 環境 | 確かめ方 |
| --- | --- |
| デスクトップの Chrome・Edge・Firefox・Safari の最新版 | E2E テスト（Chromium・Firefox・WebKit）と手動 |
| iOS の Safari・Android の Chrome の最新版（実機） | 手動 |

補正できない動作の違いは、README の対応環境に、ブラウザごとの制約として書きます。

## アクセシビリティ

WCAG 2.2 の適合レベル AA を目安にします（[画面](../interface/screen.md#アクセシビリティ)）。

| 性質 | 確かめ方 |
| --- | --- |
| キーボードだけですべての操作ができる | E2E テスト（`e2e/keyboard.spec.ts`）と手動 |
| 支援技術に名前と状態が伝わる | 自動検査（`e2e/accessibility.spec.ts`）とスクリーンリーダー |
| コントラスト比を満たす | `tests/interface/contrast.test.ts` |
