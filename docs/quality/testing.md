# テスト

単体テスト、生成の基準、シミュレーション、E2E テストの構成と書き方をまとめます。手動の確認は [リリースの確認](./release-checklist.md) に書きます。

関係するコード: `tests/`、`e2e/`、`tools/simulate.ts`、`tools/simulation/*`、`playwright.config.ts`、`vite.config.ts`、`.github/workflows/ci.yml`

## 構成

```
tests/
├── support/          # helpers.ts（2bar を生成する run など）、baseline.ts（基準の run とハッシュ）
├── fixtures/         # generation-baseline.json、tuned-config.json
├── generation/       # random・form・arrangement・harmony・drums・pitched-parts・fx・baseline
├── playback/         # transport・sound
├── interface/        # screen・integration・contrast
└── quality/          # performance・simulation・conventions
e2e/                  # Playwright（*.spec.ts）
```

`tests/` は仕様の文書と同じ領域に分けます。何を確かめたいかから、対応する文書とテストを引けるようにするためです。

| コマンド | 内容 |
| --- | --- |
| `npm test` | 単体テスト（Vitest、`tests/**/*.test.ts`） |
| `npm run typecheck` | 型検査（`src`・`tests`・`tools`・`e2e` と設定ファイル） |
| `npm run e2e` | ビルドしてから E2E テスト（3つのブラウザエンジン） |
| `npm run simulate -- --bars 4096 --seed 42` | 音声なしの長時間の生成と統計 |

## 単体テスト

- 機能の規則は、実装に近い単位（関数・生成器）と、アンサンブルで長く生成した結果の性質の両方で確かめる。性質のテストは、複数のシードとパラメーターの組（`SEEDS`・`PARAM_SETS`、0 と 1 の端を含む）で、2048〜8192bar を生成して調べる
- 再生側の時刻の計算（ダッキング、オートメーション、再開位置、クリップの計数）は、Tone.js から切り離した関数を直接呼ぶ。オートメーションは、点列を Web Audio と同じ規則（`set`・直線・指数のランプ）で評価する関数をテスト側に持ち、`fxStateAt` と照らし合わせる
- 設定ファイルの検証は、キーごとの表で型違い・範囲外・関係の崩れ・知らないキーを確かめ、`config.example.json` がコードの既定値と一致することを確かめる
- 試聴で決める値（重み、確率）は、テストに書き写さない。テストは性質（範囲、単調性、出現）を確かめる
- `describe` は「領域: 対象」の形（`drums: fill` など）で名付ける

## 生成の基準

`tests/generation/baseline.test.ts` は、記録した基準（`tests/fixtures/generation-baseline.json`）と、今の生成のハッシュが一致することを確かめます。

| 記録した run | 内容 |
| --- | --- |
| 既定の設定 | 5つのシードとパラメーターの組（全スライダーを上げた組と下げた組を含む） |
| スライダーを動かし続ける | 2bar ごとにスライダーの値を変える。2bar・8bar・32bar の境界でのラッチを通す |
| 調整した設定ファイル | `tests/fixtures/tuned-config.json` を `parseConfigText` で読み、2つのシードで生成する |

- どれも 2048bar 分を生成し、10個のパート（構成・キー・音色・ドラム・sub・reese・stab・pad・鳴る側のイベント・FX）ごとにハッシュを取る。不一致になったとき、どのパートが変わったかが分かるようにするため
- ハッシュするのは音を決める値だけで、`Context` を丸ごとは入れない。オブジェクトのキーを並べ替えてから直列化する。内部の形や組み立ての順を変えただけで不一致にならないようにするため
- 設定ファイルの run では、警告がないことと、生成の数値の全グループと初期値が既定値と違うことも確かめる。値が黙って無視されて、既定値の基準を2回取っただけになるのを防ぐため

**基準を記録し直すとき**: 生成を変えるつもりのない変更（リファクタリングなど）では、基準を記録し直しません。不一致は誤りとして直します。生成を変えるつもりの変更では、試聴で確かめたうえで記録し直し、同じシードの展開が変わることをリリースノートに書きます。

## 慣習の検査

`tests/quality/conventions.test.ts` は、`src`・`tools`・`tests`・`e2e` に要件の番号とフェーズの名前が出てこないこと、テストのファイル名にフェーズの名前がないことを確かめます。コメントと名前は、それだけで理由が分かる文で書きます。文書へのリンクや番号に頼ると、文書の構成が変わったときに古くなるためです。

## コントラストの検査

`tests/interface/contrast.test.ts` は、`src/ui/styles/tokens.css` の明るい配色と暗い配色について、画面の意味を持つ塗り方（文字、操作部品の境界、フォーカスの枠、メーター、スペクトラム、ミュートとソロなど）を1つずつ挙げた表で、コントラスト比を計算します。塗り方を足したら、この表にも足します。シーケンサーの打音と音は、ベロシティの濃淡を見せるための例外として表に入れません（[画面](../interface/screen.md#決めた理由)）。

## シミュレーション

`tools/simulate.ts` は、指定した小節数を音声なしで生成し、統計を出力します（`--json` で JSON）。`--m2`・`--m8`・`--m32`・`--energy`・`--fill`・`--initial-key`・`--seed`・`--bars` と、`--config <パス>`（画面と同じ規則で設定ファイルを読む。コマンドラインで明示した値が優先）を受けます。

| 統計 | 用途 |
| --- | --- |
| パート別・層別の密度、32bar の役割ごとの密度 | 変化率とエネルギーの効き方 |
| 2bar・8bar の反復率、基準パターンの変化の回数 | 変化の量 |
| 進行（骨組み）・色付けしたコード・借用和音・テンションの出現数 | 和声の確率の効き方 |
| パートごとのノート数、型の出現数、音度の分布、コード外・音域外・音階外の音の数（0 になるはず） | 音程のあるパートの規則 |
| サイクルの長さ・レイアウト・入り方の出現数、シーンごとの小節数と密度、シーンで鳴らさないパートの音の数（0 になるはず） | アレンジ |
| 移調の回数と初期キーからの距離ごとの小節数、音色の出現数と切り替えの回数、FX の出現数 | サイクルごとの変化 |
| 2bar の生成時間 | 性能 |

反復率は、直前の2bar とイベント列が一致した2bar の割合（ベースは構成音の番号で、スタブとパッドは位置と長さで比べる）と、直前の8bar と基本パターンが一致した8bar の割合です。設定ファイルの数値を変えたときの統計を、試聴の前に確かめるのに使います。`tests/quality/simulation.test.ts` が統計の性質を確かめます。

## E2E テスト

画面の状態と操作を、配布と同じ base path でビルドしたページに対して、Playwright で Chromium・Firefox・WebKit の3つのブラウザエンジンで確かめます。

| ファイル | 確かめること |
| --- | --- |
| `initial.spec.ts` | 初期画面の部品とタイトル。停止のボタンが押せない |
| `playback.spec.ts` | 再生・一時停止・再開・停止でのボタン・欄・累計。表示の切り替え |
| `menu.spec.ts` | 右から出て、タブを切り替え、閉じるボタンでだけ閉じる。ミュートとソロの状態 |
| `startup.spec.ts` | クエリ文字列のシード、設定ファイル（壊れた JSON を含む） |
| `share.spec.ts` | URL とシードの有無、鳴っている展開のシード、閉じ方、コピー |
| `media-session.spec.ts` | ページが登録したメディア操作の処理を呼ぶと、画面のボタンと同じ変化になる |
| `narrow.spec.ts` | 幅 320px と 375px で、横にはみ出さず、1小節のシーケンサーと全幅のメニュー |
| `keyboard.spec.ts` | Tab キーだけでの再生・メニュー・共有、タブの矢印キー、メニューに覆われた部品にフォーカスが移らない（幅 320・1024・1280px） |
| `accessibility.spec.ts` | 初期画面・再生中・メニュー・共有のダイアログで、axe（WCAG 2.2 AA までのタグ）が違反を報告しない |

**E2E テストで確かめないもの**

| 対象 | 理由 | 代わりの確かめ方 |
| --- | --- | --- |
| 音の中身 | ヘッドレスのブラウザでの音の出力は環境に左右され、テストが不安定になるため | 単体テスト・シミュレーション・試聴 |
| OS のメディアキー、ロック画面、通知 | テストから OS の操作を起こせない | ページの処理の呼び出しを E2E テストで、OS からの操作を手動で |
| クリップボードへの実際のコピー（Chromium 以外） | テストから読み取りの権限を与えられない | Chromium だけで読み返し、ほかは手動で |
| 実機の Safari・iOS・Android | Linux で動かす WebKit は Safari と同じではない | 手動 |

**書き方**

- 再生していることは画面の状態（再生のボタンの名前、累計の表示）で確かめ、何小節進んだかは確かめない。進み方は音声のクロックとマシンの負荷で変わるため
- 固定の時間を待たず、Playwright の自動の待ち（`expect(…).toHaveText` など）を使う。メニューを開いた後は、滑り込みが終わるまで待ってから位置を測る
- 再試行は 0 回にする。再試行は、ときどきしか通らないテストを隠すため
- 設定ファイルは `page.route` で `config.json` の中身を返す。ページから見ると、配布先に置いたときと同じ取得になる。ビルドを分けると CI の時間が延びるため
- メディア操作は `page.addInitScript` で登録された処理を控えて呼ぶ。Media Session API がないブラウザでは同じ形の代わりを置く
- Chromium は `--autoplay-policy=no-user-gesture-required` で起動する。音の出力先のない環境でも AudioContext を止めないため
- Firefox は、音の出力先がないと AudioContext が起動しないので、CI では PulseAudio を出力先のない機器（null sink）だけで起動しておく
- メディア操作の処理は `MediaSession.prototype.setActionHandler` を包んで受け取る。WebKit は、セッションのオブジェクトそのものに置いた関数を呼ばなかったため
- 「横にはみ出さない」は `scrollWidth ≤ clientWidth`、「覆われていない」はフォーカスのある要素の中心と四隅の少し内側の5点で `elementFromPoint` を呼び、どれか1点でその要素か子孫が返ることで確かめる

**安定性**: リリースの前に、同じコードで `npx playwright test --repeat-each 10` を実行し、すべて通ることを確かめます。

## CI

`.github/workflows/ci.yml` が、プルリクエストの作成と更新のたびと、main の更新で、型検査・単体テスト・ビルド・E2E テストを回します（[連携](../interface/integration.md#cicdgithubworkflowsciyml)）。テストを1つ失敗させると CI が失敗することは、リリースの前に一度確かめます。
