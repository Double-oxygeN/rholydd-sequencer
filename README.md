# Rholydd Sequencer

/ˈr̥ɔlɨð ˈsiːkwənsə/

## 概要

Rholydd Sequencer は、パラメーターを設定するだけでドラムンベースのビートをランダムに展開しながら永久に鳴らし続ける、ブラウザ向けのジェネレーティブ・シーケンサーです。完全なランダムではなく、2bar・8bar・32barそれぞれの単位でまとまりのある展開になるよう変化率を制御します。

## 特徴

- **永続的な音楽再生**: 再生ボタンを押せば、ユーザーが止めるまで新しいパターンを生成し続けます。一時停止すると、再開したときに止めた位置の続きから鳴ります。
- **階層変化**: 2barの基本ループ、8barのセクション、32barのフレーズという3階層で、変化の種類と量を使い分けます。
- **展開の起伏**: 128〜192barのサイクルでイントロ・ビルド・ドロップ・ブレイクダウンを巡り、ライザーやインパクトなどの FX で切り替わりを演出します。ドロップへの入り方は、無音の溜め・ピックアップのスネア・パッドだけ残す溜め・溜めなしの4つから選び、サイクル内の2つのドロップで必ず変えます。サイクル内では主題を共有し、2回目のドロップで同じ主題が戻ってきます。サイクルの頭では、ときどきその時点のキーの属調・下属調に移調し、五度圏を巡っていきます。リースベース・スタブ・パッドの音色もサイクルごとに選び直します。
- **和声の色合い**: コードにテンション（9th・11th・13th など）を加え、iv と v の位置ではドリア・フリギア・和声的短音階から借りた IV7・♭IImaj7・V7 に置き換えることがあります。テンションは上モノだけが鳴らし、ベースはコードの構成音を保ちます。
- **簡素な画面**: 初期画面は再生の操作、累計の小節数とサイクル数、位置のメーター、シーケンサーかスペクトラムアナライザーだけです。パラメーターとミキサー（ソロ付き）は右上から開くメニューにあります。幅 320px のスマートフォンでも、はみ出さずに全体を表示します。
- **メディア操作**: メディアキーや OS のロック画面・通知から、再生・一時停止・停止できます。
- **反復パターン**: 各区間を、基準となる区間に対する関係（反復・変奏・転換）として決め、シード付き乱数で生成します。反復は同じ形で再現され、変奏と転換が要所で変化を生みます。
- **DnBらしさの維持**: ステップごとの重み表とパートごとの変異しやすさにより、ランダムでもジャンルの文法を崩しません。
- **拡張前提の設計**: 全パートが共通インターフェースの生成器として実装され、ベース・ウワモノ・FXを後から追加できます。
- **再現性**: シード値を保存すれば、同じ展開をもう一度聴けます。`?seed=12345` のように URL で初期シードを指定できます。右上の共有ボタンから、聴いている展開のシードを含めた URL をコピーできます。

## 技術スタック

| 領域 | 採用技術 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript | イベント型やコンテキスト型を厳密に定義するため |
| ビルド | Vite | 開発サーバーが速く、静的アセットの扱いが簡単 |
| 音声 | Tone.js（Web Audio API 上） | Transport による先読みスケジューリングに加え、フェーズ2以降の合成音源・エフェクトをそのまま使えるため |
| タイマー | Tone.js の Worker クロック | メインスレッドの負荷でテンポが揺れるのを防ぐため |
| 乱数 | 自前実装の sfc32（シード派生は splitmix32） | 再現性と階層ごとのシード派生のため |
| UI | Vanilla TS（MVP） | MVP の UI は最小限のため。拡張時にフレームワーク導入を再検討 |
| テスト | Vitest | 生成器を音声なしで単体テスト・統計検証するため |

## ディレクトリ構成

生成（何を鳴らすか）と再生（いつ鳴らすか）をディレクトリレベルで分離しています。生成器は音を出さず、イベント列だけを返します。

```
rholydd-sequencer/
├── public/samples/drums/    # kick, snare, hat, ghost の WAV（tools/make-samples.ts で合成した自作の音）
├── src/
│   ├── units.ts             # brand 型の基盤、0〜1 の値
│   ├── engine/
│   │   ├── transport.ts     # 再生・一時停止・再開・停止、2bar ごとの生成要求、ダッキングと FX の予約
│   │   ├── playhead.ts      # 一時停止した位置と、生成済みの2bar の保持
│   │   ├── resume.ts        # 再開位置以降に鳴らすイベントの切り出し
│   │   ├── tuning.ts        # 音の調整用の数値（トリム、ダイナミクス、FX の範囲など）と既定値
│   │   ├── audio.ts         # 音源、ミキサー、バス、リバーブ、コンプレッサー、リミッター、FX とスイープ用フィルター
│   │   ├── patches.ts       # リース・スタブ・パッドの音色の表と、その制約
│   │   ├── automation.ts    # FX のイベントからオートメーションの点列と、再開位置での値を求める
│   │   ├── ducking.ts       # キックの時刻からダッキングのエンベロープを求める
│   │   ├── clip.ts          # ピークとクリップの計数
│   │   └── clip-worklet.ts  # クリップ検出の AudioWorklet
│   ├── structure/
│   │   ├── conductor.ts     # 小節位置 → コンテキスト、パラメーターのラッチ、サイクルと進行とキーと音色の保持
│   │   ├── arrangement.ts   # サイクルのレイアウトとドロップの入り方、シーン、シーンごとのエネルギーとパート
│   │   ├── form.ts          # 区間の関係（反復/変奏/転換）
│   │   ├── energy.ts        # 32bar のエネルギーカーブ（ドロップで使う）
│   │   ├── harmony.ts       # コードの表（ダイアトニックと借用和音）とテンション、進行の色付け、移調
│   │   ├── tuning.ts        # 構造の調整用の数値（和声の確率、エネルギー、レイアウト）と既定値
│   │   ├── key.ts           # キーとナチュラルマイナーの音階、初期キーからの移調
│   │   └── timbre.ts        # 音色の名前の表と、サイクルごとの音色の選択
│   ├── generators/
│   │   ├── types.ts         # Generator インターフェース、イベント型、ドラムの確定結果を含むコンテキスト
│   │   ├── ensemble.ts      # コンダクター → ドラム → 音程のある4パート → 選別 → FX の順に2bar を生成
│   │   ├── arrange.ts       # シーンで鳴らすパートの選別と、ドロップの入り方に従った溜め
│   │   ├── line.ts          # 音程のあるパートに共通の規則（型の選択、シード、コードトーン）
│   │   ├── pitch.ts         # 音域への折り返しと積み上げ
│   │   ├── tuning.ts        # パートの調整用の数値（フィルの長さ、構成音の重み、ベロシティ）と既定値
│   │   ├── drums/
│   │   │   ├── weights.ts   # ステップ重み表、パート別設定
│   │   │   ├── pattern.ts   # 2bar パターンの型と操作
│   │   │   ├── constraints.ts # 基本パターンの制約
│   │   │   ├── base.ts      # 基本パターンの初期生成
│   │   │   ├── mutate.ts    # 変異（8bar の変奏、32bar の強い変異）
│   │   │   ├── transition.ts # 転換（B）のパターン
│   │   │   ├── thin.ts      # エネルギーによる間引き
│   │   │   ├── ornament.ts  # 装飾
│   │   │   ├── fill.ts      # フィル（8bar 末と32bar 末の大きなフィル）
│   │   │   ├── compose.ts   # 層の合成
│   │   │   └── index.ts     # ドラム生成器
│   │   ├── sub/             # サブベース（リズムの型、音域とオクターブ跳躍、生成器）
│   │   ├── reese/           # リースベース（リズムの型、生成器）
│   │   ├── stab/            # スタブ（リズムの型、生成器）
│   │   ├── pad/             # パッド（声部連結のボイシング、生成器）
│   │   └── fx/              # FX のイベント（ライザー、スイープ、インパクト、スロー、溜め）
│   ├── random/rng.ts        # シード付き PRNG、シード派生
│   ├── params/
│   │   ├── store.ts         # パラメーター管理
│   │   ├── mixer.ts         # ミキサー（ソロを含む）とダッキングの設定
│   │   ├── config.ts        # 設定ファイルの検証と既定値との合成
│   │   ├── load-config.ts   # config.json の読み込み
│   │   └── query.ts         # クエリ文字列のシード
│   ├── ui/                  # 再生の操作とメディア操作、累計とメーター、ステップグリッド、スペクトラムアナライザー、メニュー、パネル、ミキサー、共有
│   └── main.ts
├── tools/
│   ├── simulate.ts          # オフライン長時間生成と統計出力
│   └── make-samples.ts      # ドラムサンプルの合成
├── tests/
├── config.example.json      # 設定ファイルの全キーと既定値
└── docs/                    # 要件定義書、設計書、ロードマップ
```

## セットアップ

必要環境は Node.js 24.2 以上（`tools/simulate.ts` が `import.meta.main` を使うため）と、Web Audio API に対応したモダンブラウザ（Chrome / Firefox / Safari / Edge の最新版）です。

```bash
git clone <repository-url> rholydd-sequencer
cd rholydd-sequencer
npm install
npm run dev
```

ブラウザの自動再生制限により、音声は画面上の再生ボタンを押した時点で開始されます。

## 設定ファイル

`public/config.json`（配布時は `index.html` と同じ場所の `config.json`）を置くと、ページを開いたときに読み込み、パラメーターとミキサーの初期値や、生成と音の調整用の数値を上書きします。書き方は `config.example.json` を参照してください。書いたキーだけが上書きされ、ファイルがない場合や書かれていないキーはコードの既定値を使います。型や範囲の合わない値は無視し、ブラウザのコンソールに警告を出します。同じシードでも、設定ファイルの生成の数値が違えば別の展開になります。

## 開発コマンド

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバーを起動 |
| `npm run build` | 本番用ビルド |
| `npm test` | 単体テストを実行 |
| `npm run simulate -- --bars 4096 --seed 42` | 音声なしで長時間生成し、密度・反復率・32bar の役割ごとの密度・進行・各パート・サイクルとシーン・ドロップの入り方・移調・音色・FX の統計を出力（`--m2` `--m8` `--m32` `--energy` `--fill` `--initial-key` `--json` も指定可。`--config <パス>` で設定ファイルを読む） |
| `npm run samples` | ドラムサンプルを `public/samples/drums/` に合成し直す |
| `npm run typecheck` | 型検査 |
